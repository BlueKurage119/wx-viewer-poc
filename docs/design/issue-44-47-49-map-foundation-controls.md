# Issue #44・#47〜#49 地図基盤・操作コントロール設計

作成日: 2026-09-15  
対象 Issue: #44 (F1)、#47 (F4)、#48 (F5)、#49 (F6)

## 1. 目的と設計承認の対象

防災気象情報ビューを、端末台帳で解決した会場を基準にした Leaflet 地図へ置き換える。背景には国土地理院の淡色地図を表示し、その上にダークテーマの時間操作カード、凡例、ズームおよび会場復帰の操作を配置する。

本書は、ユーザーが承認したワイヤフレームを画面構成の正とする。既存の `docs/basic-design.md` §4.3 にある「レイヤー選択を地図左上へ置く」配置案は、今回確定した「時間操作カード左上のドロップダウン」へ置き換える。背景地図、会場基準位置、可視矩形への中心補正、操作面のダークテーマ、全幅の下部通知領域は確定事項である。一方、ナウキャスト／キキクルの実画像、実在カタログ、最新追従、取得失敗の状態は本書の実装対象に含めない。

対象となるのは次である。

| Issue | この設計で実装する責務 |
| --- | --- |
| #44 F1 | Leaflet の地図本体、淡色地図、会場マーカー、可視矩形の中心補正、地図の標準ドラッグ・ホイール操作 |
| #47 F4 | 地図内下部中央の時間操作カードの枠、選択・再生操作を外部状態へ通知する UI、キーボード操作 |
| #48 F5 | 時間カード左上のレイヤー選択、凡例の開閉、地理院タイルの出典表示 |
| #49 F6 | 左下の拡大・縮小、現在地形アイコンだけの会場復帰、画角再計算の呼び出し |

## 2. 前提と外部サービス

### 2.1 会場と表示範囲

会場は URL から既存の `resolveTerminal` が解決した `terminal.venue` を受け取る。地図は `terminal.venue.weatherTargets` を基準に推測せず、会場台帳にある `mapReference` を使用する。現在の値は `east` が東京ビッグサイト、`trc` が東京流通センターである。地図移動、ズーム、レイヤー選択は右側情報カードの対象を変更しない。

初期ズームは **10** とする。これは、現時点で API #39/#40 が許可する気象タイルのズームが `[10]` であり、背景だけを先に高精細化して後続の気象レイヤーが描けない状態を初期画角にしないためである。背景地図自体の最小・最大ズームは国土地理院の淡色地図に合わせて **5〜18** とする。

### 2.2 背景地図と出典

Leaflet の `TileLayer` は次を使う。

```text
https://cyberjapandata.gsi.go.jp/xyz/pale/{z}/{x}/{y}.png
```

`minZoom: 5`、`maxZoom: 18`、`attribution` は `地理院タイル` とし、画面の常時表示出典は国土地理院の地理院タイル一覧へのリンクとする。国土地理院は、Web サイトやアプリケーションでのリアルタイム読込みを、出典明示と一覧ページへのリンクにより申請不要で利用できるとしている。淡色地図の日本周辺の提供ズームも 5〜18 と明記されている。利用条件を実装時にも改変せず、出典をメニュー内だけに隠さない。

Leaflet は `leaflet` とその CSS を `apps/web` に追加する。React-Leaflet は導入しない。地図インスタンスの生成・破棄、Leaflet のイベント解除、`invalidateSize`、タイル層の差替えを `MapViewport` の React effect に集約する。CSS は `leaflet/dist/leaflet.css` のような CSS import とし、既存の `sideEffects` 制約に反する JavaScript の bare import を増やさない。

標準マーカー画像の URL 自動解決には依存しない。会場マーカーは React/CSS で管理する SVG を `L.divIcon` として渡すか、Leaflet の `CircleMarker` として描画し、Vite のアセット解決差異でマーカーが消えないようにする。マーカーには会場名を `aria-label` としたフォーカス可能な操作を設けず、地図上の位置を示す非操作要素とする。

### 2.3 行政界の扱い

会場対応の市町村境界は、国土地理院の淡色地図に描かれた行政界を読む。F1 は GeoJSON、ベクトルタイル、外部 CDN その他の独自境界レイヤーを取得・同梱・重ね描画しない。会場の位置は常設マーカーだけで示す。これにより、背景地図の利用条件と出典表示を一元化し、独自境界データの更新・帰属管理を持ち込まない。

## 3. 画面構造とレスポンシブ方針

既存 `AppShell` はヘッダー、72px のナビレール、共通通知領域の高さを主領域から既に差し引く。防災気象情報ビューはその `view-content` を余白・通常スクロールなしの `WeatherMapView` に替え、以下を内部に重ねる。通知領域は地図外なので中心計算へ再度差し引かない。

```text
WeatherMapView（シェルから与えられる主領域全体）
├─ MapViewport（Leaflet のコンテナ、背景・会場マーカー）
├─ MapInformationColumnSlot（右端、G1 が後から実カード列を渡す）
├─ MapLegend（左上、初期表示）
├─ MapAttribution（右下、常時表示）
├─ MapZoomControls（左下、＋／－／会場復帰アイコン）
└─ TimelineControlCard（右カード列を除く地図の下部中央）
   ├─ LayerSelector（左上のドロップダウン）
   ├─ SelectedFrameSummary（選択レイヤー、日時、実況／予報等の状態）
   ├─ FrameSlider
   └─ FrameTransport（前、再生／停止、次、最新へ）
```

右側情報列は G1 の責務であり、F1〜F6 では内容を実装しない。ただし F1 は `informationColumnRef` を受け取り、G1 が実装されるまで同じ位置・幅を占める `MapInformationColumnSlot` を配置する。これは会場中心補正のためのレイアウト予約であり、情報カードの見出し、アイコン、データ、スクロール内容を持たない。G1 はこの slot の内部を不透明なダークカード列にし、列全体とカード間の余白を一つのスクロール操作面にする。

フル HD（1920×1080）と iPad 横向き（1024×768）を確認基準にする。CSS は固定の画面寸法にせず、主領域に対する `clamp` とコンテナ幅を使う。右列はおおむね `clamp(18rem, 25vw, 28rem)`、時間カードは右列を除く領域内で `min(36rem, calc(100% - 2 * 安全余白))` を上限とする。カードが利用可能幅を超えないことを優先する。iPad 横向きでは右列と時間カードがともに収まり、さらに狭いウィンドウではカードの横幅を縮め、操作ボタンを 2 行に折り返す。地図、右列、時間カード、左上凡例は互いの前面関係を明示した z-index トークンで管理する。

ダークテーマの操作面には、`--md-sys-color-surface-container*`、`--md-sys-color-on-surface*`、`--md-sys-color-outline*`、`--md-sys-color-primary*` など既存テーマ生成値だけを使う。背景地図は淡色のままとし、読み上げ・ボタン・カードの色を地図画像から継承しない。警報・注意報などの意味色は F1〜F6 に追加しない。

## 4. F1: 会場を可視矩形に置く地図基盤

### 4.1 中心補正

地図コンテナのサイズを `(W, H)`、右の情報列の実幅を `R`、下部時間カードの実高を `B` とする。可視矩形は、地図座標で次の範囲である。

```text
x: 0 .. W - R
y: 0 .. H - B
```

会場を置くべき画面内座標は `((W - R) / 2, (H - B) / 2)` である。Leaflet が画面中央 `(W / 2, H / 2)` に置く地図中心は、会場の Web Mercator 座標を使って次で求める。

```text
mapCenter = unproject(
  project(venue.mapReference, zoom) + (R / 2, B / 2),
  zoom,
)
```

実装は `map.project` / `map.unproject` を使い、緯度経度を画面比率で直接加減算しない。`R` と `B` が 0 のときは通常の会場中心と一致する。算出後 `setView(mapCenter, initialZoom, { animate: false })` を呼び、初期表示ではタイル読み込み後の見かけの移動を避ける。

時間カードは下部中央だが、可視矩形ではその**高さ全体**を差し引く。これはワイヤフレームで承認された遮蔽補正であり、カードの横幅や左上凡例、左下ズーム群は計算対象に入れない。右列はカード間の地図が見える部分も含め、列全体の幅を差し引く。

### 4.2 再計算の契機

`ResizeObserver` で以下の要素を観測する。

1. `MapViewport` 本体の content rect
2. 右側情報列 slot の border-box rect
3. 時間操作カードの border-box rect

各 observer callback は同期で `setView` を呼ばず、`requestAnimationFrame` に一つだけ再計算を予約する。カードや列の CSS 変更で同一フレームに複数通知が来ても、最新の `getBoundingClientRect()` から一回だけ計算する。地図コンテナ寸法が変化したときは先に `map.invalidateSize({ pan: false })` を行い、その後に初期／復帰要求がある場合だけ補正中心をセットする。アンマウント時は observer と予約済み frame を解除する。

リサイズだけではユーザーの閲覧位置を壊さない。状態は `viewPlacement: 'initial' | 'manual' | 'returning'` とする。

| 契機 | 地図中心・ズーム |
| --- | --- |
| 初回の map ready とレイアウト計測完了 | 可視矩形へ会場を置き、初期ズーム 10 |
| 「会場へ戻る」 | 現在の実寸 `R` / `B` で再計算し、初期ズーム 10 |
| 右列／時間カードのサイズ変化、ウィンドウリサイズ | `initial` の初期レイアウトが未確定な間だけ再計算。完了後、または `manual` では `invalidateSize` のみ |
| ドラッグ、ホイール、＋／－ | `manual` にし、中心補正をしない |

初期レイアウトが「未確定」かは、3 要素が一度以上正のサイズを報告し、`document.fonts.ready` 後の animation frame を通過した時点で確定とする。これにより Web フォントやカード折返しで高さいが変わる前の誤った会場位置を固定しない。右列が一時的に未マウントの場合は幅 0 とせず、slot を常設して測る。

### 4.3 地図操作とアクセシビリティ

Leaflet は PC のドラッグ、ホイールズーム、キーボード操作を有効にする。ホイールが右カード列・時間カード・凡例にあるときは、その領域側でスクロールまたは操作を消費し、地図へ伝播させない。右カード列のスクロールは G1 が引き継ぐ。

地図コンテナには `aria-label="会場周辺の地図"` を付ける。Leaflet の attribution control は非表示にして、F5 の常時表示リンクに集約する。操作ボタンには日本語の `aria-label` と tooltip を付け、現在地アイコンは視覚的なピン／照準アイコンだけにし、テキストの「会場へ戻る」は常時描画しない。キーボードで操作できる順序は、凡例の閉じる／再表示、レイヤー選択、時間操作、ズーム、会場復帰とする。地図そのものへフォーカスした利用者をカードへ強制移動しない。

## 5. F4: 時間操作カード

### 5.1 表示と責務分割

時間操作カードは右列を除いた地図領域の下部中央に常設する。選択レイヤーのドロップダウンを左上に置き、同じ行の右側へ「選択日時」と実況／予報等の時刻性質を表示する。中段は利用可能フレームのスライダー、下段は「前」「再生／停止」「次」「最新へ」の四操作とする。ワイヤフレームどおり、バー上には実況・予報という文字を繰り返さず、フレームの種類に応じた MD3 トークン色で区間を示唆する。スクリーンリーダーには各目盛りの時刻性質を `aria-valuetext` で明示する。

F4 が持つのはカードの構造、フォーカス、入力を `onIntent` で伝えることだけである。時刻選択、再生中の一覧固定、最新追従、窓外コマの保持と置換禁止は F7 が所有する。F4 は次の表示モデルを受け取るため、F2/F3 未実装中も fixture によりカードを操作可能に検証できる。

```ts
type TimelineFrameKind = 'observed' | 'forecast' | 'reference';
type TimelineFrame = Readonly<{
  id: string;
  displayTime: string;
  kind: TimelineFrameKind;
  enabled: boolean;
}>;
type TimelineViewModel = Readonly<{
  layerLabel: string;
  selectedFrameId: string | null;
  selectedFrameLabel: string;
  frames: readonly TimelineFrame[];
  playing: boolean;
  latestAvailable: boolean;
}>;
type TimelineIntent =
  | { type: 'select-frame'; frameId: string }
  | { type: 'previous-frame' }
  | { type: 'toggle-play' }
  | { type: 'next-frame' }
  | { type: 'select-latest' };
```

`frames` が空のときはスライダーと前／再生／次を disabled にし、「利用可能な時刻はありません」とカード内に表示する。F4 は欠け、前回値、停止理由を創作しない。F8 が後から状態表示を加える余地として、選択日時の隣に `status` slot を持たせる。`reference` はキキクルの危険度判定基準時刻など、実況／予報の二分法に当てはめない表示に使う。

再生はクリック・Space・Enter で切り替え可能な単一ボタンにする。スライダーの矢印キー、Home、End は標準 range 操作を通して `select-frame` を送る。カードは 1 秒間隔、一覧固定、新着反映の時機を決めず、F7 の view model を描画する。`最新へ` は F4 では `select-latest` intent であり、地図位置やズームを変えない。

### 5.2 実装上の分担

`TimelineControlCard` は F4、`LayerSelector` と `MapLegend` は F5 とする。F4 は左上領域を `layerSelector` slot として提供し、F5 はその slot に選択 UI を載せる。これによりワイヤフレームの一体感を保ちつつ、レイヤー定義・凡例との対応を F5 に閉じ込める。

## 6. F5: レイヤー選択、凡例、出典

レイヤーは単一選択であり、初期選択は「雨雲ナウキャスト」とする。メニューには「雨雲ナウキャスト」と「キキクル」を置き、キキクル選択時にだけ「大雨」「浸水」「土砂」を第2階層または同一メニュー内の選択肢として示す。初回のキキクル選択は大雨、以後の種別保持は F3 の状態責務である。洪水、雷、竜巻、複数レイヤー同時重ね合わせは選択肢に出さない。

F5 は以下の型を使い、F2/F3 が実レイヤー定義を提供するまでは固定の UI fixture で描画する。

```ts
type MapLayerId = 'nowcast' | 'kikikuru-heavyrain' | 'kikikuru-inund' | 'kikikuru-land';
type LegendItem = Readonly<{ label: string; swatchToken: string }>;
type LayerPresentation = Readonly<{
  id: MapLayerId;
  label: string;
  legendTitle: string;
  legendItems: readonly LegendItem[];
  sourceLabel: string;
}>;
```

メニューからの選択は `onLayerSelect(id)` で外部へ通知し、F5 自身は実画像や時刻を変更しない。F2/F3 は選択確定後に中心・ズームを維持して該当カタログを表示し、F7 が必要なら再生・時刻状態を調整する。

凡例は初期表示する。凡例に閉じるアイコンボタンを置き、閉じた後は時間カード内のレイヤー選択の隣に、アイコンだけの「凡例を表示」ボタンを常に残す。凡例の領域は左上に固定し、操作面を不透明なダークカードにする。実データの階級・単位・色は F2/F3 が定義するため、F5 の fixture を実仕様の凡例として出荷しない。レイヤー濃度の操作は実画像描画をする F2/F3 の実測と不可分であるため、F5 ではコントロールを表示せず、F2/F3 設計へ引き継ぐ。これは、未検証の透過度を UI だけで確定させないためである。

出典は、地図コンテナ右下に `地理院タイル` の常時表示リンクとして置く。右カード列、時間操作カード、通知領域の下に隠れず、リンクの focus ring とタップ領域を確保する。気象レイヤーの出典は F2/F3 の実データ表示と同時に追加する。

## 7. F6: ズームと会場へ戻る

左下に、上から拡大、縮小、現在地形アイコンの順で縦配置する。ズームは Leaflet の `zoomIn` / `zoomOut` を呼び、背景地図の 5〜18 に従い、端では該当ボタンを disabled にする。各操作は `manual` を記録する。ボタンの視覚ラベルは `＋`、`－`、現在地形アイコンのみとし、補足テキストを常時出さない。

会場復帰は `returnToVenue()` を呼び、現在の右列幅・時間カード高を再計測して §4.1 の中心とズーム 10 を設定する。時刻、選択レイヤー、レイヤー種別、凡例の開閉、再生、最新追従を変更しない。アイコンには `aria-label="会場の初期位置に戻る"` を付ける。会場マーカーをクリックした場合にも、この復帰操作を暗黙に実行しない。

## 8. 後続 Issue との境界

| 後続 | 引き継ぐもの | この設計で先取りしないもの |
| --- | --- | --- |
| F2 | `MapViewport` の Leaflet instance、可視サイズ、`MapLayerId='nowcast'`、時間カードの `TimelineViewModel` / intent 接点 | N1/N2 候補の選択、API 再読込、PNG URL、Z10 タイルの拡縮方式、実凡例、濃度 |
| F3 | 同上。キキクル3種の選択枠と `reference` 時刻表示 | 各 layer の catalog、初回大雨・種別保持の状態、画像・実凡例、未来時刻の意味 |
| F7 | F4 の intent と描画用 view model | 最新追従／手動保持、再生中一覧固定、窓外選択時の案内、再生停止後の新着反映 |
| F8 | 時間カードの `status` slot、レイヤー表示領域 | 欠けコマ、未取得、停止、前回画像を成功や降水なしに見せない表示 |
| G1 | `MapInformationColumnSlot`、会場固定、測定 ref | カード内容、カード間の見た目、一覧のスクロール・データ取得 |

気象タイル API は現時点で許可ズームを `[10]` と返す。F2/F3 は Leaflet の現在ズームをそのまま API パスの `z` として送ってはならない。背景地図の 5〜18 と気象タイルの取得可否を混同せず、Z10 タイルをどの表示ズームで拡縮するかは実画像を使う F2/F3 の受け入れ検証で決定する。

## 9. 受け入れ条件と検証

### 9.1 共通の検証環境

製造後、`npm run lint`、`npm run typecheck`、`npm run format:check`、`npm run test -w apps/web` を実行する。UI 実測では Web フォント適用完了後に、ブラウザの主領域を 1920×1080 と 1024×768 相当にし、右列にスクロールバーがある条件でも確認する。ネットワークを遮断した状態でも、地図タイルの失敗が操作カードや会場復帰の JavaScript 例外にならないことを確認する。

### 9.2 F1 (#44)

- [ ] `east` と `trc` の各端末 URL で、台帳の `mapReference` に対応する会場マーカーが表示される。
- [ ] 初期表示および会場復帰直後、`map.latLngToContainerPoint(mapReference)` が、右列幅と時間カード高さを除いた可視矩形の中心から ±2 CSS px 以内にある。ヘッダー、ナビレール、通知領域を二重控除しない。
- [ ] 地図をドラッグ・ホイール・＋／－で操作できる。操作後にウィンドウを拡縮しても、中心・ズームが会場へ強制的に戻らない。
- [ ] 初期レイアウト計測中にカード高・右列幅が変わっても、フォント適用後に可視矩形の中心へ収束する。
- [ ] 背景が淡色地図で地名・行政界を読め、5〜18 の範囲でズームできる。会場対応の市町村境界を背景地図から読め、独自境界レイヤーが重ね描画されない。
