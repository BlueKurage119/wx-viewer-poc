# Issue #57 アメダスパネル設計

## 1. 対象と確定判断

[Issue #57](https://github.com/BlueKurage119/wx-viewer-poc/issues/57) の G6 を対象とする。east は江戸川臨海、trc は羽田の観測所値を表示し、会場地点の観測値として扱わない。パネルは気温、湿度、風向、風速、直近1時間降水量と観測時刻、詳細は直近24時間の推移を扱う。期間選択、極値、日集計、品質注記は対象外とする。基本設計 §5.10 の確定事項と、§5.13 の設計案のうち本 Issue で採用された範囲に従う。

ヒアリングで次を確定した。

1. 風向コード1〜16は公式資料または公式画面の対応表で全対応を確認できた場合だけ方位名へ変換する。気象庁公式画面の辞書と地点 JSON の参照経路を確認できたため、本設計では §5 の対応を採用する。
2. AQC 5/6は欠測相当、AQC 1/4の品質注記は表示しない。
3. 「非提供」と「欠測」は要素別に表示する。通信異常はパネル全体で表示し、保持した前回値があればその観測時刻も示す。

## 2. 現行実装との境界・依存

- `packages/shared/src/weatherApi.ts` の `AmedasResponse` は station、metadata、data、capabilities を持つ。5要素の値は `number | null | undefined`、観測列は `observedAt` 昇順である。`null` は欠測、キー不在は要素の値なし、`capabilities.unsupportedElements` は地点の非提供を表す。各値の AQC や `isEstimated` は公開 DTO に存在しない。表示側で品質意味や推計状態を作らない。
- `apps/api/src/services/weatherApiService.ts` の `getAmedas` は会場の地点を解決し、観測列と非提供要素を返す。training/test は `unavailable` と `data: null` を返す。既存 API 契約を使い、画面から他会場の値を要求しない。
- 現行の `WeatherMapView.tsx` は `useAmedas` を通して既存のアメダス枠へ実 API のカードを渡す。`apps/web/src/map/panels/amedas/` に本文・モデル・スタイルがあり、詳細は4グラフと5項目の観測表を描く。今回の UI 監修はこれら既存実装を調整する。#58・#59 の作業フォルダやファイルは対象にしない。
- #52 の `InfoPanelFrame` は stale も装飾なしの content とする。#60 は CLOSED だが、この現行動作にアメダス固有の異常表示はない。共通枠全体の状態規則を変更せず、本カードの本文で更新不能と前回値時刻を示す。通信失敗を確認できた場合だけ「通信異常」とする。保持値がない失敗では既存 failed 本文をアメダス向け表示にする最小の拡張、またはカード本文側で同等の表示を行う。他パネルの状態表示は変更しない。基本設計 §5.12 の一般的な stale 方針は本 Issue で確定しない。
- 詳細の枠、フォーカス復帰、右列スクロール復帰は #61 の `DetailDialog` を使う。グラフはアメダス固有の内容として実装し、#61 の共通表を無理に流用しない。
- G6 が trc を表示するには C17 #144 の両地点収集と E5 #37 の会場別 API が動作していることが前提である。値が保存されていない状態を羽田の「非提供」とみなさない。

## 3. データ・状態・表示

`GET /api/weather/amedas` を選択端末と制御状態で取得し、既存の情報別 API クライアントと同じ再取得・終了処理を使う。`venueId`、`terminalId`、`controlStatus`、`isTraining`、`metadata.availability` を維持し、レスポンスの対象が選択端末と違う場合は採用しない。`metadata.issuedAt` を観測時刻に代用せず、最新観測行の `observedAt` を使用する。日時は日本時間で日付・時分まで表示する。

利用可能な `data.observations` から `latestObservedAt` と一致する行を選び、その一つの時刻の5要素だけを表示する。該当行がなければ値を合成せず取得不能として扱う。各要素は `unsupportedElements` に含まれれば「非提供」、提供対象で値が `null` またはキー不在なら「欠測」、有限数値なら数値を表示する。0は有効な観測値として表示する。負値の気温も保持する。羽田の湿度は非提供。単位は気温 ℃、湿度 %、風速 m/s、降水量 mm。パネルの降水量見出しは「時雨量」とし、値は `precipitation1h` のまま扱う。詳細では1時間積算値であることを明示する。時刻の異なる要素を寄せ集めない。

`available` は通常表示。`stale` かつ保持値ありなら同じ値を表示し、パネル本文と詳細の上部に「前回値：{観測時刻}」を示す。`stale` だけでは通信異常と断定できないため、原因が不明なら「更新できていません」と表示する。HTTP 通信失敗が画面で確認できた場合は「通信異常」と「前回値：{観測時刻}」を表示する。保持値なしの `unavailable`、通信失敗、初回未取得では数値を出さず、原因に応じて「取得できません」「通信異常」「取得中」を表示する。前回値の時刻は `fetchedAt` や `lastSuccessAt` ではなく `observedAt` である。AQC 5/6 の欠測化は既存正規化・保存契約を維持し、画面では `null` を欠測表示する。AQC 1/4 の注記は加えない。

## 4. 詳細ダイアログ

現在時刻（API の `evaluatedAt`、通信失敗時は画面の現在時刻）を終端とする直近24時間を固定表示する。API の昇順観測列を時刻で絞り、気温・湿度・風速は折れ線、1時間降水量は棒グラフにする。各系列に単位、時刻目盛、値を読み取る手段を設ける。風向は同じ観測時刻に対応する値を参照できる一覧またはグラフ上の時刻ごとの説明を置く。期間選択は置かない。非提供系列は「非提供」、値が `null` またはキー不在の時刻は「欠測」とし、欠測を0へ変換せず、線で補間しない。降水棒は各観測時刻を終点とする1時間値であり、重なる時間帯の値を合計しない。取得済みの最古時刻より前と、stale 時の最終観測時刻から現在までなど、24時間内の未取得範囲を明示し、実データにない時刻の値を作らない。観測値の不規則な時刻間隔を等間隔の連続観測と誤認させない。全系列0件でも詳細枠は取得状態を説明する。

色は既定の MD3 トークンを使い、色だけで状態や系列を区別しない。HEX 直書きはしない。見ればわかる重複ラベルを増やさない。詳細の時刻・値・欠測・非提供はキーボードと読み上げでも到達できるようにし、#61 の開閉・フォーカス復帰を維持する。

### 4.1 UI 監修の確定事項（2026-09-28）

- パネルの各ラベルは対応する値より上に偏らないよう、気温・湿度／風向・風速／時雨量の各組の位置をそろえる。既存の2列配置を維持し、実画面でラベルと値の上下関係・隣接組との整列を確認する。
- パネルでは `precipitation1h` の見出しを「時雨量」、単位を mm とする。詳細のグラフまたは観測表の近くに「時雨量は各観測時刻を終点とする直前1時間の積算値」と簡潔に示す。データ系列・計算は変更しない。
- 詳細上部の24時間範囲と未取得範囲は、一行程度の短い時刻要約に整理する。24時間の開始・終了と、期間内に未取得部分があることを保持する。期間開始側と現在側のどちらが未取得かを区別できる表示と読み上げを用意し、長い説明文を上部に複数行重ねない。狭幅では自然な折り返しを許す。
- 観測表は新しい観測時刻から古い順に並べる。初期表示は現在から直近3時間に入る取得済み行とし、同じ24時間範囲内に古い行が残る場合だけ「続きを見る」を出す。操作ごとに次の3時間分を追加表示し、24時間の全行まで到達できる。境界の時刻を二重表示せず、欠測や観測間隔の空きでも順序を維持する。追加分が0行でもさらに古い取得済み行があるなら、空の時間帯を飛ばして次の取得済み行まで到達できるようにする。グラフの表示期間は操作に連動させず常に24時間固定とする。
- 観測表の5項目（気温、湿度、風向、風速、時雨量）を維持する。羽田湿度の非提供セルは視覚上「—」としてよい。ただし同じ「—」を欠測の表示に使わず、欠測は「欠測」の文字で示す。非提供セルには `aria-label` 等で「湿度 非提供」を与え、表の列見出し・観測時刻との対応も読み上げられるようにする。パネルの羽田湿度も「—」を使う場合は、値のアクセシブル名を「湿度 非提供」とする。数値0、欠測、非提供、通信異常の区別を残す。
- 詳細のクリック・開閉はユーザー実機で問題なしと確認済み。今回の修正で #61 の挙動を壊さないことを回帰確認する。

## 5. 風向コードの根拠と変換

[気象庁「地域気象観測システム（アメダス）」](https://www.jma.go.jp/jma/kishou/know/amedas/kaisetsu.html) は風向を16方位で表すことを示す。[気象庁「配信資料に関する仕様 No.13302」](https://www.data.jma.go.jp/suishin/shiyou/pdf/no13302) の10分・時別値ファイル説明 p.7 と日別値ファイル説明 p.12 には、0=静穏、1=NNE、2=NE、3=ENE、4=E、5=ESE、6=SE、7=SSE、8=S、9=SSW、10=SW、11=WSW、12=W、13=WNW、14=NW、15=NNW、16=N の全対応がある。ただし同 PDF はバイナリ統計値ファイルの仕様であり、本サービスが利用する `bosai/amedas/data/point` JSON の仕様とは明記されていない。

[取得方法レポート](../data-acquisition-report.md) §5 は実 JSON のコード8と「0は静穏」を記録する。[#19 設計](issue-19-amedas-normalization.md) §2.3.4・§3.5 は公式画面スクリプトが辞書を参照することを確認したが、当時は辞書本体を実読できていなかった。2026-09-28 に[気象庁公式アメダス画面](https://www.jma.go.jp/bosai/map.html#contents=amedas&elem=wind) のページ内スクリプトを確認した。`Amedas.Const.WDR_INFO` は `{0:'静穏',1:'北北東',2:'北東',3:'東北東',4:'東',5:'東南東',6:'南東',7:'南南東',8:'南',9:'南南西',10:'南西',11:'西南西',12:'西',13:'西北西',14:'北西',15:'北北西',16:'北'}` を保持する。同じ画面処理が `DK.wdr='windDirection'`、`C.windDirectionElems`、`j=Amedas.Const.WDR_INFO`、`m.tr(j[n.toString(10)])` を用いる。したがって公式画面は地点 JSON の `windDirection` のコードをこの辞書の方位名へ直接変換している。全項目が上記公式 PDF の表とも一致する。

この公式画面の直接参照を根拠に、コード0〜16を上記の日本語方位名へ変換する。整数以外・範囲外の数値は方位名を推定せず「方位不明」とする。`null` とキー不在は §3 の「欠測」または「非提供」を優先する。現在の公式画面実装を根拠としているため、画面側の辞書が将来変わった場合は再照合する。極値の風向や日界にはこの判断を拡張しない。
