# Issue #193 性能検証記録

## 実行条件

- 実行日時: 2026-09-22T05:13:13Z
- OS: Darwin 25.6.0 x86_64
- Node.js: v24.20.0、SQLite 3.53.4 (`better-sqlite3`)
- CPU: Intel Core i7-9750H 2.60GHz（論理12コア）
- メモリ: 32GiB、プロセス最大RSS 7,532,864KiB
- DB: 生成fixture 50,000件、原文約991 bytes/件、DB 97,906,688 bytes
- 分布: `normal / VPWS50` 50,000件。末尾2,500件を両会場対象外、その前を east / trc 交互とした。
- 設定: `yieldEveryParsedReceptions=25`、`candidatePageSize=100`
- コマンド: `node --import tsx apps/api/scripts/measureWarningRecovery.ts 50000`

スクリプトは同一生成DBに対して、まず設計基準コミット `e9d312e` 相当の全履歴昇順解析を実測し、現況を保存する。次に現況表だけを空にして新方式を実測し、ID以外のストリーム・スナップショット・明細が基準結果と一致することを検証する。生成DBは終了時に削除する。

プロセスCPUは user 113,459.69 ms / system 55,330.42 ms。最大RSSは比較基準の全履歴解析を同一プロセスで先に実行した値を含む。
