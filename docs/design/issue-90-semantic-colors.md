## 1. 確定した範囲と根拠

警戒レベル 2〜5 と通知区分「警報・問いかけ・非常ブザー」のセマンティックカラートークンを定義し、既存の警報行・問いかけ行へ適用する。**対象外**: 状態色、受信異常バナー、非常ブザーの UI 実装、警戒レベルの新規 UI、通知判定ロジックの変更（初版から変更なし）。

参照資料:

- `docs/issues-draft.md` A5（元の範囲から上記へ限定）
- `docs/basic-design.md` §5.7【確定】: 気象庁公式の警戒レベル配色（レベル5・特別警報=黒／レベル4・危険警報=紫／レベル3・警報=赤／レベル2・注意報=黄。レベルを冠さない種別も同段階の色）。「具体的な配色値（コントラスト調整、ダークモード対応等）は画面実装時に別途調整する」とあり、本書がその調整にあたる。色は補助であり文字でも段階が分かることも同§で確定。
- `docs/basic-design.md` §5.7【確定】（3周目で追記）: **レベル5・特別警報のダークモード表現**。共通シェルがダーク固定であるため、純粋な黒（背景と同化する）ではなく「黒と紫の中間色を背景、紫を縁取り、黄を文字色」とする。配色系統としての「黒」は変更せず、視認性確保のための画面実装値の確定であり、HEX値・トークン化は本書に委ねられている。
- `docs/basic-design.md` §7.2: 通知区分（警報／問いかけ／非常ブザー）と気象警報は別概念。よって両者のトークンは値が近くても統合しない。非常ブザーは「問いかけの特殊モード」であり、ヘッダーを赤表示して鳴動する（緊急度の主たるシグナルはこのヘッダー表現であって、通知行の背景色ではない）。
- `docs/basic-design.md` §7.4 コード対応表【確定】（4周目で参照追加）: 非常ブザーはコード 43 / 48 / 49（レベル4危険警報）と 32 / 33 / 35 / 36 / 37 / 38 / 39（特別警報・レベル5）から生成される。すなわち非常ブザーは「危険警報以上」と実際に強く結びついた通知区分であり、警戒レベル4・5と同じ紫の色相ファミリーで表すことに根拠がある。
- `CLAUDE.md` §8.4: 警戒レベル色・通知区分色は MD3 基盤の対象外で「別途セマンティックトークンとして定義する」。色の HEX ハードコード禁止（§3.2）。
- `apps/web/src/theme/applyTheme.ts`（テーマ適用経路。`themeFromSourceColor` + `palettes.neutral.tone()` で書き出す既存方式）、`apps/web/src/theme/seeds.ts`（`DEFAULT_THEME_SEED = '#1A73E8'`）、`apps/web/src/index.css`（通知行の暫定 HEX 直書き）、`apps/web/src/shell/NotificationArea.tsx`
- インストール済み `@material/material-color-utilities` 0.3.0 の実物（`palettes/core_palette.js`、`palettes/tonal_palette.d.ts`）。`CorePalette` のコンストラクターが `a1 = TonalPalette.fromHueAndChroma(hue, Math.max(48, chroma))`、`n1 = fromHueAndChroma(hue, 4)` であることをソースで確認した。すなわち `themeFromSourceColor(seed).palettes.primary` は「シードHEX から MD3 標準手順で導いたトーナルパレット」そのものであり、既存 `applyMd3Theme` がアプリ全体テーマを作る手順と同一である。

今回のヒアリング確定事項:

- **できるだけ Material Design の世界観を維持する。** 配色は「Material の標準パレットを参考にしたシード値」から MD3 のトーン生成で導く。任意の hue/chroma を直接指定する初版の方式は採らない。
- **気象庁配色（黒・紫・赤・黄）は死守する。** シード選定はこの色相ファミリーの範囲内で行う。
- **レベル5はダークモードでの視認性を優先し、「黒紫中間の塗り + 紫の縁取り + 黄の文字」で表現する**（3周目の確定。上記 §5.7 追記に対応）。統括担当がビジュアル比較で示した近似値は container `#22102f` / outline `#7148af` / on-container `#ffd400` 付近であり、これは**最終値ではなく方向性の指示**である。本書はこの近似値に最も近い MD3 トーンをシードベース生成から選び、コントラスト基準を満たすことを実測で確かめて確定させる。
- **バッジにハッチング・斜線等のパターン処理は行わない**（3周目の確定）。段階の表現は塗り・縁取り・文字色と、§5.7 で確定した文字表記のみで行う。
- **アプリ全体のシード（`DEFAULT_THEME_SEED`）に依存させない。** ユーザーがテーマシードを変えても警戒色の色相が変わってはならないため、本トークンは各カテゴリ専用の固定シードのみから生成し、`harmonize` もしない。
- コントラスト基準（文字/背景 4.5:1 以上、境界/背景 3:1 以上）を維持する。
- **非常ブザーは紫系で表す**（4周目の確定）。上記 §7.4 の対応表により危険警報以上と結びつくため、その関連を色で示す。ただし**レベル4・レベル5と同一の HEX にはしない**。紫の色相ファミリーは共有しつつ、レベル4（container tone 40）・レベル5（container 紫 tone 5 / outline 紫 tone 50）とは別のトーン、別のシードから生成する。緊急度の主たるシグナルはヘッダーの赤点滅（§7.2）であり、通知行の背景色単独で「紫が赤より危険に見えるか」を担保する必要はない。文字表記（「非常ブザー」）でも識別できることを維持する（§5.7 の「色は補助」）。
- **非常ブザーの紫は、気象庁の紫に近いマゼンタ寄りの色相とする**（5周目の確定）。統括担当が青寄りの紫（Deep Purple 700 由来、container `#6847c0`）とマゼンタ寄りの紫（Purple A700 由来、container `#9200dc`）を並べてユーザーに提示し、**後者が選択された**。したがって本書はシードを `#AA00FF` とし、レベル4との HEX 非一致は outline のトーン選定（§2.8）で担保する。
- `notice-emergency` は今回定義するが適用先 UI がなく未使用でよい（将来 UI 向け）。
- 警戒レベルトークンが light/dark 同値になること自体は問題ない。
- 実際の通知行は README 記載の「共通シェルはダーク固定」により dark でしか使われない。light の検証は将来の再利用を見越した保守的検証として残す。

電文仕様・通知区分判定は変更しない。基本設計の【設計案】【未確定】記述を本書で確定扱いしない。

## 2. 配色の生成方式

`apps/web/src/theme/semanticColors.ts` を新設する。**色の HEX 定数は「カテゴリ専用シード」としてのみ現れ、トークン値そのものは実行時に MD3 のトーナルパレットから生成する。**

### 2.1 カテゴリ専用シード

Material の標準パレット（2014 Material palette / M3 baseline）から、気象庁の色相ファミリーに合致するものを選ぶ。

| シード定数 | HEX | 出所 | 実測 HCT (hue / chroma) | 用途 |
| --- | --- | --- | --- | --- |
| `SEED_ALERT_YELLOW` | `#FFEB3B` | Material Yellow 500 | 104.0 / 62.3 | 警戒レベル2（黄）、**レベル5の文字色**、通知・警報 |
| `SEED_ALERT_RED` | `#B3261E` | Material 3 baseline error | 26.0 / 76.3 | 警戒レベル3（赤）、通知・問いかけ |
| `SEED_ALERT_PURPLE` | `#7B1FA2` | Material Purple 700 | 320.2 / 68.3 | 警戒レベル4（紫）、**レベル5の塗り・縁取り** |
| `SEED_NOTICE_EMERGENCY` | `#AA00FF` | Material Purple A700 | 315.7 / 94.3 | 通知・非常ブザー |

HCT 値は本設計時に Node 上で `Hct.fromInt(argbFromHex(seed))` を実行した実測。

**3周目でシードは4つになった。** 2周目まで存在した `SEED_ALERT_BLACK`（`#212121`）はレベル5専用だったが、レベル5が「黒紫中間 + 紫縁 + 黄文字」になったため使用先が無くなる。**未使用の定数として残さず削除する。**

**4周目で `SEED_NOTICE_EMERGENCY` を赤系 `#D50000` から紫系に差し替え、5周目でその紫を `#512DA8`（Deep Purple 700）から `#AA00FF`（Purple A700）へ変更した。** シードの本数は4本のまま変わらない。旧値 `#D50000` / `#512DA8` は使用先が無くなるため、**未使用の定数として残さず削除する**（赤系は `SEED_ALERT_RED` がレベル3と問いかけで引き続き使う）。

非常ブザー用に `SEED_ALERT_PURPLE` を再利用せず、専用の紫シードを立てた理由は次のとおり。

- `SEED_ALERT_PURPLE` を再利用してトーンだけずらす案（container tone 30 = `#721199` 等）では container は区別できるが、**outline に tone 80 を使うとレベル4の outline `#ebb2ff` と完全に同一 HEX になる**（同一パレットの同一トーンのため）。「値が近くても意味が違うトークンは統合しない」の原則からは、区別すべき2区分のロール値が偶然一致する状態は避けたい。別シードにすると container / outline がレベル4・レベル5と異なる値になる（on-container の `#ffffff` は意図した一致。§2.6 参照）。
- Material Purple A700 は Material 標準パレット（アクセント段）由来であり、**気象庁の警戒レベル4「紫」に最も近い色相ファミリー**である。HCT 色相 315.7 で、`SEED_ALERT_PURPLE`（320.2）と同じマゼンタ寄りの紫。5周目のユーザー選択（§1）に対応する。
- 採らなかった代替: Material Deep Purple 700 `#512DA8`（HCT 298.2 / 61.7）。色相が `SEED_ALERT_PURPLE` から 22 離れており、レベル4の紫との判別は容易（4周目の採用案）。ただし青寄りに寄る分、気象庁配色の紫からは離れる。ユーザーがビジュアル比較の上でマゼンタ寄りを選択したため採らなかった。
- **Purple A700 の副作用と対処**: `SEED_ALERT_PURPLE` と色相が 4.5 しか離れていないため、**同一トーンではレベル4のロール値と極めて近い色になる**。実測で outline tone 80 は `#e4b5ff` となり、`alert-level-4-outline` `#ebb2ff` との相対輝度比 1.00・CAM16 距離 2.4 で実質同色だった。そこで **outline のトーンのみ 80 → 90 にずらす**（§2.8）。container（tone 40）と on-container（tone 100）は4周目の構成を維持する。

### 2.2 シード → パレット

各シードについて `themeFromSourceColor(argbFromHex(seed))` を一度だけ実行し、その `palettes` を使う。既存 `applyMd3Theme` と同じ関数・同じ導出経路である。

- 4シードとも `palettes.primary` を使う（= `fromHueAndChroma(hue, max(48, chroma))`）。3周目でレベル5が無彩色でなくなったため、**2周目に必要だった `palettes.neutral` の特例は無くなった**。全トークンが同一の導出規則に載る。
  - 参考（採らなかった経路）: 無彩色シード `#212121` は chroma 0.9 のため `palettes.primary` が `max(48, chroma)` で chroma 48 まで持ち上げられ、hue 209.5 のシアン系パレットになってしまう（実測）。2周目はこれを避けるため neutral パレットを使っていた。3周目の配色ではこの回避自体が不要になる。
- **レベル5は2つのパレットをまたいで組む唯一のトークン群である。** container・outline は紫シードの `palettes.primary`、on-container は黄シードの `palettes.primary` から取る。実装上、レベル5のトーン指定は「パレット名 + トーン」の組で持たせ、他レベルの「単一パレット + 3トーン」と同じテーブルに無理に押し込まない。

`themeFromSourceColor` の結果はモジュールスコープでシードごとにメモ化してよい（`applyTheme.ts` の `themeCache` と同じ考え方）。ただし `createSemanticColors()` の戻り値オブジェクトは呼び出しごとに新規生成し、呼び出し側の変更が他へ伝播しないようにする。

### 2.3 トーンの決め方（MD3 のロール対応）

| 種別 | container | on-container | outline | 根拠 |
| --- | --- | --- | --- | --- |
| 警戒レベル 3・4 | tone 40 | tone 100 | tone 80 | MD3 の `primary`(light) / `on-primary` 相当。塗りつぶしバッジとして最も彩度が乗る帯 |
| 警戒レベル 2（黄） | tone 85 | tone 10 | tone 40 | 黄はトーンを上げないと「黄」として認識できない（tone 40 は暗いオリーブ `#695f00`）。明色コンテナ＋暗色前景という MD3 の light container 型の組み合わせを使う |
| 警戒レベル 5（黒紫） | 紫 tone 5 | 黄 tone 85 | 紫 tone 50 | 下記 2.7 参照 |
| 通知（警報・問いかけ）light | tone 90 / 10 / 50 | | | MD3 の `*-container` / `on-*-container`(light) と同じトーン |
| 通知（警報・問いかけ）dark | tone 30 / 90 / 80 | | | MD3 の `*-container` / `on-*-container`(dark) と同じトーン |
| 通知・非常ブザー（紫） | tone 40 / 100 / **90**（light/dark 共通） | | | 塗りつぶし型。container / on-container はレベル3・4と同じトーンだが、専用の紫シードから生成するため値は重複しない。**outline だけ tone 80 ではなく 90** を使う（レベル4 outline との重複回避。下記 2.5・2.8 参照） |

### 2.4 light/dark の扱い

- **警戒レベル 2〜5 は light/dark で同値。** 気象庁配色は状態を問わず固定するのが §5.7 の確定事項であるため、モードで色相・明度を振らない。実装上は「モード非依存テーブル」として1つだけ定義し、`dark` 引数を参照しない。
- **通知・警報／問いかけのみ `dark` で分岐する。** これらは行全体の背景であり、MD3 の container ロールとして surface 階層に馴染ませる必要があるため。
- **通知・非常ブザーはモード非依存。** 最大の緊急度を持つ表現をモードで弱めない。

### 2.5 非常ブザーを問いかけと分離した理由（実測）

初版どおり「問いかけと同じトーン構成・赤系シード」にすると、dark の container は問いかけ `#910809` と非常ブザー `#930000` になり、実測上ほぼ判別不能だった。3周目では、これを避けるため非常ブザーを赤系のまま container tone 40（`#c00000`）+ on tone 100 の塗りつぶし型とし、トーン構成のレベルで問いかけと差を付けていた。

**4周目でこれを紫系へ変更した。** 差の付け方が2重になる。

1. **色相ファミリーが違う**（問いかけ=赤系 `#B3261E` 由来 / 非常ブザー=紫系。5周目時点のシードは `#AA00FF`）。赤系同士でトーンだけ変えていた3周目より判別性が高い。
2. **トーン構成が違う**（問いかけは light/dark で container tone 90 / 30 の container 型、非常ブザーはモード非依存の tone 40 塗りつぶし型）。この構成は3周目から変えていない。

紫にする根拠は §1 のとおり `docs/basic-design.md` §7.4 の対応表【確定】であり、非常ブザーは実際にレベル4危険警報・レベル5特別警報から生成される。**赤から紫への変更で「赤より弱く見える」懸念については、§7.2 のとおり非常ブザーの主たる緊急度シグナルはヘッダーの赤表示と鳴動であり、通知行の背景色はそれを補助する識別子である**という整理を採る（§5.7 の「色は補助」の援用）。

適用先 UI は今回作らないが、将来 UI が問いかけと非常ブザーを取り違えないためのトークン設計として確定させる。

### 2.6 生成値（実測）

Node 上で `@material/material-color-utilities` 0.3.0 を実行して得た実際の HEX。コントラストは同スクリプト内で sRGB 相対輝度から独立に計算した実測値（小数第2位まで）。**テスト期待値はこの表の値を転記し、生成式をテスト側で再実装しない。**

`alert-level-5-on-container`（`#ead723`）は `alert-level-2-container` と**値が一致する**。同じ黄シードの同じ tone 85 を参照するためであり、意図した一致である。ただし**トークンは統合しない**（レベル2の塗りとレベル5の文字は役割が別で、片方だけを調整する可能性があるため）。テストの golden 値でも別々に検証する。

## 2.7 レベル5のトーン選定（実測）

`docs/basic-design.md` §5.7 の確定（黒紫中間の塗り・紫の縁・黄の文字）に対し、統括担当が示した近似値 container `#22102f` / outline `#7148af` / on-container `#ffd400` を目標に、シードベース生成のトーンから最も近く、かつコントラスト基準を満たすものを選んだ。近似 HEX は**ハードコードしない**。

| ロール | 目標近似値の実測 HCT (h/c/t) | 採用トーン | 生成値 | 選定理由 |
| --- | --- | --- | --- | --- |
| container | `#22102f` = 314.3 / 25.2 / 8.3 | 紫 primary tone 5 | `#210031` | 目標とトーンがほぼ一致（8.3 対 5）。トーンテーブルの刻み上、tone 5 が最も近い。彩度は MD3 パレット（chroma 68）由来のため目標より高いが、tone 5 では絶対的な明度が低く、見た目は「黒に紫が差した」印象になる（下記の対背景コントラスト参照） |
| outline | `#7148af` = 305.1 / 55.9 / 40.0 | 紫 primary tone 50 | `#a84fce` | 目標は tone 40（= `alert-level-4-container` `#8c33b3` と同一トーン）だが、**tone 40 では縁/塗りが 2.92、縁/`surface-container` が 2.53 でいずれも 3:1 を満たさない**（実測）。tone 45 は 3.53 / 3.06 と辛うじて満たすのみ。余裕を持つ tone 50 を採用した。レベル4と同じ紫パレットの1段明るいトーンであり、「レベル4と同系統の紫」は維持される |
| on-container | `#ffd400` = 95.4 / 63.9 / 86.2 | 黄 primary tone 85 | `#ead723` | 目標とトーンがほぼ一致（86.2 対 85）。`alert-level-2-container` と同じトーンを使うことで、黄の見えがレベル2と揃う |

レベル5固有のコントラスト実測（すべて本設計時に Node 上で計算）:

| 組み合わせ | 実測 | 基準 |
| --- | --- | --- |
| 文字 `#ead723` / 塗り `#210031` | 12.84 | ≥ 4.5 |
| 縁 `#a84fce` / 塗り `#210031` | 4.22 | ≥ 3.0 |
| 縁 `#a84fce` / `--md-sys-color-surface-container`（dark 実測 `#1f1f23`） | 3.66 | ≥ 3.0（レベル5固有の追加基準。下記） |

**レベル5だけ「縁 / 周囲の背景」も基準の対象に加える。** 他レベルは塗り自体が背景から十分浮くのに対し、レベル5は塗りが背景とほぼ同じ明度（1.15）であり、バッジの輪郭は縁取りだけが担うためである。ハッチング等のパターンは使わない（§1 の確定事項）ので、この縁が唯一の境界表現になる。

なお `#1f1f23` はアプリのテーマシード（`DEFAULT_THEME_SEED`）から生成される値であり、シードを変えると変動しうる。上表の 3.66 はデフォルトシードでの実測であり、**この1組だけはテーマシード依存**である。テストの自動判定にはこの組を含めず（§5-4 の対象外）、目視確認（§5-6）と受け入れ条件で担保する。

## 2.8 非常ブザーの outline トーン選定（実測、5周目）

`SEED_NOTICE_EMERGENCY = #AA00FF` は `SEED_ALERT_PURPLE = #7B1FA2` と HCT 色相が 4.5 しか離れていない（315.7 対 320.2）。そのため他トークンと同じ tone 80 を outline に使うと `alert-level-4-outline` とほぼ同一色になる。**この Issue の一貫した原則（§2.6・4周目）により、`notice-emergency` はレベル4・レベル5と HEX を一致させない**ため、outline のトーンだけをずらす。

判定基準は2つ。

- (A) `alert-level-4-outline` `#ebb2ff` から知覚的に離れていること。**目安は CAM16 距離 6.0 以上**とした。根拠は、4周目の outline `#cebdff` の対 `#ebb2ff` 距離が 6.0 であり、その値がビジュアル比較にかけられた際に「レベル4の縁と区別が付かない」という指摘は出ていない、という消極的な実績である（この数値自体が弁別閾として検証されたわけではない。§8 に未確認事項として残す）。
- (B) 境界/背景コントラスト（縁 `outline` / 塗り `container #9200dc`）が 3.0 以上（§1 の基準）。

`themeFromSourceColor('#AA00FF').palettes.primary` の各トーンでの実測は次のとおり。

| トーン | 生成値 | 縁/塗り（対 `#9200dc`） | 縁/`surface-container`（`#1f1f23`） | 対 `alert-level-4-outline` `#ebb2ff` CAM16 距離 | 対 `alert-level-5-outline` `#a84fce` CAM16 距離 | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| tone 70 | `#d48fff` | **2.82** | 7.17 | 6.4 | 9.3 | (B) 不合格（3.0 未満） |
| tone 75 | `#dca2ff` | 3.27 | 8.33 | **4.2** | 10.7 | (A) 不合格（6.0 未満） |
| tone 80 | `#e4b5ff` | 3.79 | 9.66 | **2.4**（相対輝度比 1.00） | 12.1 | (A) 不合格。実質同色 |
| tone 85 | `#ecc7ff` | 4.36 | 11.09 | **4.8** | 13.5 | (A) 不合格（6.0 未満） |
| **tone 90** | **`#f4d9ff`** | **4.98** | 12.68 | **7.2** | 14.8 | **採用**（A・B とも合格） |

**tone 90 を採用する。** (A)(B) を同時に満たす唯一のトーンであり、4周目の実績値 6.0 を上回る 7.2 の距離を確保する。トーンを下げる方向（70・75）は `alert-level-4-outline` の tone 80 に明度で近づく上、下げるほど `alert-level-5-outline`（tone 50 相当の `#a84fce`）にも近づくため、**上げる方向にしか解が無い**ことを実測で確認した。

tone 90 は彩度が下がる（HCT chroma 23.3）ため、単体では淡い藤色に見える。ただし本トークンの用途は彩度の高い container `#9200dc` の上の縁取り・行の仕切りであり、そこでは縁/塗り 4.98 の明快な境界として働く。**単独の面（塗り）としては使わない**ことを §7 に引き継ぐ。

## 3. 公開トークンと API

トークン命名は初版のまま維持する。

```ts
export type AlertLevel = 2 | 3 | 4 | 5;
export type NoticeColorCategory = 'warning' | 'question' | 'emergency';
export type SemanticColorRole = 'container' | 'on-container' | 'outline';
export type SemanticColorToken =
  | `--wx-alert-level-${AlertLevel}-${SemanticColorRole}`
  | `--wx-notice-${NoticeColorCategory}-${SemanticColorRole}`;

/** カテゴリ専用シードのみから生成する。アプリのテーマシードは受け取らない。 */
export function createSemanticColors(dark: boolean): Record<SemanticColorToken, string>;
```

計 21 トークン（4 レベル × 3 + 3 区分 × 3）。値は `hexFromArgb` の出力（小文字 7 文字の `#rrggbb`）。型・関数は `apps/web/src/theme/index.ts` から re-export する。

内部の分割（シード定数、パレット取得のメモ化、トーンテーブル、トークン組み立て）は製造担当の裁量でよい。ただし `dark` を参照する箇所が `notice-warning` / `notice-question` の2カテゴリに限られることは、コード上で読み取れる形にする。

## 4. 適用

### 4.1 テーマ適用経路

`applyMd3Theme(seed, dark, root)` 内、既存の MD3 トークン書き出しの後に `createSemanticColors(dark)` の 21 トークンを同じ `root.style.setProperty` で書き出す。既存 MD3 トークンの生成・`colorScheme` 設定・`index.html` の FOUC 対策は変更しない。副作用のみの bare import は追加しない（CLAUDE.md §8.1）。

`applyMd3Theme` の第1引数 `seed` は意味色の生成に**渡さない**。異なるシードで意味色が変わらないことをテストで担保する（§5-3）。

### 4.2 通知行と周辺 UI の階調（今回の追加検討）

現状（dark 固定運用）の実測値:

- `.notification-area` の背景 `--md-sys-color-surface-container` = `#1f1f23`（`DEFAULT_THEME_SEED` の neutral tone 12）
- 行の仕切り `--md-sys-color-outline-variant` = `#44474f`。surface-container に対するコントラストは **1.77**

これに対し、本設計の dark の通知行 container は surface-container に対して **1.77（警報 `#4f4800`）／1.75（問いかけ `#910809`）**。既存の仕切り線が surface に対して作っている段差とほぼ同じ大きさであり、通知行は「MD3 の surface 階層の中の1段」として読める。既存の暫定 HEX（`#3d3220` / `#45272a`）が持っていた「暗いところに色だけ乗っている」印象を、MD3 の container トーン（tone 30）に置き換えることで解消する。

これに伴い、`index.css` の適用方針を初版から次のとおり整理する。

| 対象 | 現状 | 変更後 | 理由 |
| --- | --- | --- | --- |
| `.has-notice.warning-row` の背景・文字 | `#3d3220` / `#ffe0a6` | `var(--wx-notice-warning-container)` / `var(--wx-notice-warning-on-container)` | HEX 直書きの解消 |
| `.has-notice.question-row` の背景・文字 | `#45272a` / `#ffdadb` | `var(--wx-notice-question-container)` / `var(--wx-notice-question-on-container)` | 同上 |
| 通知のある行の `border-top` | `--md-sys-color-outline-variant` | 対応カテゴリの `-outline` | 色付き行の上では `outline-variant`（`#44474f`）が行背景に埋もれる。カテゴリ outline なら実測 5.48 / 5.51 で仕切りとして視認できる |
| 通知のある行内の操作ボタンの `border` | `--md-sys-color-outline-variant` | 対応カテゴリの `-outline` | 同上（境界/背景 3:1 基準の対象） |
| `.notification-area` の背景 | `--md-sys-color-surface-container` | **変更しない** | 上記のとおり段差が既に適正 |
| 通知のない行・操作ガイド行・通知件数 | 現状のまま | **変更しない** | MD3 の surface/on-surface-variant のまま |

ボタンの背景は `transparent`、文字は `color: inherit` のまま維持し、行の on-container を継承させる。既存の共通境界指定に勝たせるためのセレクター追加（`.has-notice.warning-row .notice-actions button` 等）は許容するが、`!important` は使わない。

受信異常バナー、ヘッダー、左ナビレール、空行には適用しない。通知行の文章と操作ボタンによる識別を維持し、色に依存するラベルを増設しない（basic-design.md §5.7 の「色は補助」）。非常ブザーが現状の実装で問いかけ行に流れる挙動は変更しない。

## 5. 検証

`apps/web/tests/semanticColors.test.ts` を新設し、既存の Node test 実行経路（`node --import tsx --test tests/*.test.ts`）を使う。新規の UI 基盤・依存は追加しない。

1. **キー網羅**: `createSemanticColors(false)` / `(true)` の各キー集合が期待する 21 キーと完全一致すること（過不足なし）。
2. **golden 値**: 各キーの値を §2.6 の表から転記した固定期待値と完全一致で照合する。生成式をテスト側で再実装しない。
3. **モード非依存性**: `alert-level-*` 12 トークンと `notice-emergency-*` 3 トークンが light/dark で同値であること。`notice-warning-*` / `notice-question-*` は light/dark で異なること（同値になったら失敗させる）。
3-2. **非重複（5周目で追加）**: `notice-emergency-container` / `notice-emergency-outline` が、`alert-level-4-container` / `-outline`、`alert-level-5-container` / `-outline` のいずれとも異なる文字列であること。`on-container` は意図した一致（`#ffffff`）があるためこの判定の対象に含めない。**この判定は完全一致のみを見るものであり、知覚的な近さは検出しない**（例: outline を tone 80 に戻すと `#e4b5ff` ≠ `#ebb2ff` なのでこのテストは通ってしまう。知覚距離は golden 値テストと §2.8 の設計値で担保する）。
4. **コントラスト**: §2.6 の表の 9 組（レベル2〜5 の4組、warning/question の light・dark の4組、emergency の1組。4周目で「7 組」の誤記を修正）について、文字/背景 ≥ 4.5、境界/背景 ≥ 3.0 を判定する。sRGB 相対輝度は golden 値の HEX からテスト内で独立に計算する（`@material/material-color-utilities` の contrast API を使わない）。レベル5の「縁 / `surface-container`」はテーマシード依存のため、このテストの対象に含めない（§2.7 末尾）。
5. **書き出し**: `setProperty` を記録する最小の root stub を渡して `applyMd3Theme` を実行し、(a) 21 トークンが全て書かれること、(b) 異なる2つのシード（例 `#1A73E8` と `#B3261E`）で意味色の値が完全一致すること、(c) light→dark→light で値が元に戻ることを確認する。DOM 全体は模倣しない。
6. **目視**: 開発画面の既存通知プレビューを dark（および light 切替）で表示し、警報行・問いかけ行の computed style が該当トークンの解決色と一致すること、文字とボタン境界が読み取れること、通知のない行が通常色のままで配置が崩れないことを確認する。警戒レベルは適用先 UI がないため、一時的な色見本ファイルで確認し、**一時ファイルは必ず削除する**。恒久的なプレビュー機能は作らない。色見本は次を満たす形で作る（ハッチング等のパターンは使わない）。

- レベル2〜5のバッジ相当（塗り + 1px 相当の縁 + 文字）を、`--md-sys-color-surface-container` を背景にした面の上に並べる。
- レベル5のバッジの輪郭が背景から判別でき、黄文字が読めること、レベル4の紫と系統は同じだが段階として区別できることを確認する。
- 同じ色見本に `notice-emergency` の3ロール（塗り + 縁 + 白文字）も並べ、レベル4の紫バッジと隣接させて確認する（5周目に確認内容を更新）。**塗り同士（`#9200dc` と `#8c33b3`）は色相が近く、隣接させても「同系統の紫」に見えるのが正しい状態である**（ユーザーがマゼンタ寄りを選択した帰結。§2.6）。目視で確認するのは次の2点に限る。
  - 縁（`#f4d9ff`）がレベル4の縁（`#ebb2ff`）と並べたときに、より淡い別の色として読めること。
  - `notice-question` の赤と取り違えないこと。
7. **red の確認（対照実験 → 意図的破壊）**: まず意味を変えないコメント追加だけの改変でテストが全て通ること（対照実験）を確認する。その後、次の3つを一つずつ一時的に施し、対応するテストが実際に失敗することを確認して都度復元する。
   - `alert-level-5` の outline トーンを 50 → 40 に変更（→ golden 値テストと、境界/背景 3:1 判定のコントラストテスト。tone 40 の実測は 2.92 で基準割れになる）

## 7. 後続 Issue への引き継ぎ

- 警戒レベルバッジ UI（basic-design.md §5.7・ナビレールのバッジ §3.1）は `--wx-alert-level-{2-5}-*` を使う。段階順・種別名の表記は §5.7 の確定事項に従い、色だけで段階を伝えない。レベルを冠さない種別に独自のレベル表記を追加しない。
- **レベル5のバッジは縁取りが必須である。** 塗りが背景とほぼ同じ明度（対 `surface-container` 1.15）であり、`--wx-alert-level-5-outline` を描かないとバッジの形が消える。他レベルと同じ「塗りのみ」の実装で済ませない。縁の太さは実装時に決めてよいが、1px 未満に潰さない。ハッチング等のパターンは使わない（§1）。
- ナビレールの最高危険度バッジ（§3.1）のように**サイズが小さい**場所でレベル5を出す場合、縁取りが視認できる下限サイズがあるかは本書では未検証。小サイズでの見えは、そのバッジを作る Issue で改めて目視確認すること。
- `--wx-notice-emergency-*` は今回未使用。非常ブザー UI を作る Issue が最初の利用者になる。**マゼンタ寄りの紫系**の塗りつぶし型（専用シード `#AA00FF` の container tone 40 + 白文字）である前提で、行背景として使うなら周囲との段差（surface-container に対して 2.55）が他の通知行より大きいことを踏まえて配置する。
- **`--wx-notice-emergency-outline`（`#f4d9ff`, tone 90）は縁取り・仕切り線専用である。** レベル4 outline との重複回避のため他トークンより明るいトーンを採っており（§2.8）、彩度が低い（HCT chroma 23.3）。**面の塗りやバッジの背景として使わない**こと。白文字を載せる用途にも使わない（`#ffffff` とのコントラストは 1:1 に近い）。
- 非常ブザーの紫は「危険警報以上との関連付け」を担うが、**警戒レベル4・5のトークンとは別値である**（§2.6）。非常ブザー UI を作る Issue で、警戒レベルバッジと非常ブザー行を同一画面に同時表示する場合は、紫が2系統並ぶことになる。**とくに5周目の配色では container 同士の知覚差が小さい**（CAM16 距離 4.6）。両者が別の意味であることは文字表記で担保し、色だけで読ませない。同一画面で並べる設計になった時点で、改めて目視確認すること。
- **非常ブザーの緊急度は、通知行の色ではなくヘッダーの赤表示と鳴動（basic-design.md §7.2）が担う。** 非常ブザー UI を作る Issue は、行背景を紫にしたことでヘッダー側の赤表現を弱めない（両者は別の役割である）。
- 状態色（`available` / `stale` / `unavailable`）と受信異常バナーは本 Issue の対象外。単純な OK/NG に潰さない方針（CLAUDE.md）を維持して別途設計する。
- 訓練通知（§3.4）の「訓練」バッジは本トークン群の対象外。本番相当の警戒色をそのまま流用して実発表と誤認させない設計が必要。
- light モードのトークンは現在どの画面でも実表示されない。ヘッダー等を light 対応する Issue が最初の実利用者になる。

## 8. 実挙動未確認の事項

- 本書の HEX・コントラスト値は Node 上でライブラリを実行した実測値だが、**ブラウザー上の computed style としては未確認**（受け入れ条件 6・8・9・9-2 で製造・検収が確認する）。
- レベル5の配色は数値上の基準を満たすことのみ確認した実測であり、**実画面での見えは未確認**（受け入れ条件 9-2 の目視で確認する）。統括担当がビジュアル比較で示した近似値そのものではなく、MD3 トーンへ寄せた値である点に注意。
- **非常ブザーの紫（5周目）は適用先 UI がないため、実画面での見えは未確認。** 数値上の基準充足とレベル4/5との値の非一致・CAM16 距離のみ実測で確認した。統括担当がユーザーに提示したビジュアル比較は container `#9200dc` 相当の色を含んでいるが、**Artifact 上での比較であって、本アプリの dark シェル上での見えは未確認**である。受け入れ条件 9-2 の色見本で目視確認する。
- **`notice-emergency-outline` に tone 90 を選んだ判断（§2.8）の妥当性は、数値（CAM16 距離 7.2、縁/塗り 4.98）でのみ裏付けられている。** 「4周目の実績値 6.0 以上」という目安は、4周目の案が統括担当のビジュアル比較で許容されたという事実から導いた基準であり、CAM16 距離の一般的な弁別閾として検証したものではない。実画面で縁の違いが読み取れなかった場合は、トーンをさらに上げる余地はない（tone 95 は `#fcecff` でほぼ白）ため、シードの見直しに戻ることになる。
