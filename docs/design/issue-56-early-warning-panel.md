# Issue #56 G5. 警報級の可能性パネル 設計書

## 1. 目的・範囲

`GET /api/weather/early-warning` の `near`（VPFD61）と `far`（VPFW60）を、東京地方の「警報級の可能性」パネルに結線する。パネルには近距離の現在を含む直近3コマ、詳細ダイアログには近距離・遠距離を通した時間軸を表示する。対象は両会場とも東京地方。履歴、API・DB・共通 DTO の変更、他パネルの変更は含めない。製造ブランチの想定名は `feature/issue-56-early-warning-panel`。

## 3. データと時間軸

`near` / `far` の各 `WeatherDataset` を独立に扱い、`metadata.availability`、`issuedAt`、`data` を保持する。`timeDefines` の `timeId` と `cells.refId` は**同じ segment 内だけ**で照合し、配列添字や segment をまたぐ ID 一致で結合しない。列は `timeFrom` の昇順、同時刻なら `timeTo`、`sequence` の順とする。日付・時刻は JST で表示し、列見出しは提供区間の始終または日付を示す。詳細では固定コマ数で切り捨てない。パネルに限り §4 の3コマ表示を適用する。

発表日を JST 日付で求め、近距離はその電文の提供区間を維持し、遠距離は発表日から数えて明々後日以降の列だけを表示する。遠距離電文に残る明後日の列は表示しない。近距離が未取得でもこの境界を遠距離の発表日から求める。異なる発表日の電文が混在したときは各 segment の発表日を基準にし、同一の実時間区間を二重に表示しない。両系列の同一区間が衝突した場合は近距離を優先し、遠距離の重複列を除く。重複のない全区間は閲覧可能にする。

表示名への対応は原文の既知の `phenomenonCode` / `phenomenonName` を明示的に対応付ける。近距離の大雨→大雨、土砂災害→土砂災害、雪→大雪、風（風雪）→暴風（雪）、波→波浪、潮位→高潮。遠距離の雨→大雨・土砂災害の結合セル、その他は同じ対応を使う。未知の現象を既知行に推測で割り当てない。未知現象が来た場合は原文名の追加行に表示し、提供値を失わない。既知行は値が片側だけでも固定順で表示するが、両側とも現象自体が無い行は省く。

## 4. パネルと詳細

パネル本文には `near`（明後日まで）だけを表示し、`far`（明々後日以降）の表・時刻・状態を置かない。現在時刻を含む区間（`timeFrom <= now < timeTo`）を起点に、時間順の次の2区間まで最大3コマを選ぶ。現在を含む区間がなければ、未来の最初の区間から最大3コマとする。未来の区間もなければ「表示できる時間帯はありません」と示し、保持済みの全期間は詳細で閲覧できる。境界 `now=timeTo` は次の区間に属する。`now` は一回だけ取得し、列選択と行抽出に同じ値を使う。パネルに横スクロールは設けない。

パネル表の左上角セルは #55 のパネルと同じく文字なしとし、「現象」は表示しない。列見出しは日付を省いて `12-18` 等の時刻だけを表示する。パネルの行見出しは **大雨、土砂災害、大雪、暴風（雪）、波浪、高潮** の順とし、選択した最大3コマ内に `rankValue='高'` または `'中'` が一つ以上ある行だけを表示する。対象外の行と、`なし`・値なし・欠測だけの行はパネルから省く。表示対象になった行の3コマでは `なし` と値なしを同じ文字なしの黒セル、欠測を `?` として表示する。選択したコマに該当行が一つもなければ「警報級の可能性はありません」と示す。未知現象も同じ抽出規則で、該当すれば既知の六行の後に原文名で表示する。`far` にだけ `高`・`中` があってもパネルの行を増やさない。パネルの詳細入口は行の有無に関係なく残す。

共通枠 `InfoPanelFrame` は本パネルに限り、ヘッダーに「明後日まで: 9/28 05:00発表」のような近距離のラベル付き時刻を表示できる入力を設ける。既存 `data` 状態の単一時刻から機械的に出す時刻は重複表示しない。他パネルの時刻表示は現行どおりとする。`near.metadata.issuedAt` が `null` でデータがあるときは「明後日まで: 発表時刻不明」、保持値のない取得不能時は「明後日まで: 未取得」、初回取得中は #55 と同じくカードヘッダーに発表時刻・取得中ラベルを表示しない。本文の既存スケルトンで取得中を示す。stale の保持時刻は装飾なしで表示する。`far` だけ取得できても、パネルは近距離の未取得状態を表示し、遠距離の値を代用しない。パネルの本文・ヘッダーには遠距離の時刻や取得状態を重複表示せず、詳細で扱う。

詳細は一つの表とし、§3 の全列を時間順に並べる。行見出しはパネルと同じ固定順を使い、詳細では `高`・`中` の有無によって行を絞らない。大雨・土砂災害の近距離セルはそれぞれの値を表示する。遠距離の雨は、二行を縦に結ぶ一つのセル（`rowSpan=2` 相当）として描画し、その列に対して一回だけ読み上げられるよう「大雨・土砂災害、○日、雨の警報級の可能性、高」のようにラベルを付ける。近距離に片方だけ存在しても、詳細の行順と遠距離の結合は維持する。遠距離の雨が無い列は結合せず、各行の欠けた値を個別に扱う。

詳細表には既存の `DetailTimeSeriesTable` を使用する。列の `at` は元の `timeFrom`、下段の `timeLabel` は提供区間の時刻または日区間の表示とし、区間の見出しは「12-18」のように「時」を付けない。パネルの区間見出しにも同じ表記を使う。終了時刻が翌日の JST 0時なら、開始日の終端として `24` を使い、`18-24` や `12-24` と表示する。詳細の日付上段は区間開始日のままとし、翌日 `0` に置き換えない。共通部品の **日付＋時刻の二段見出し**をそのまま出す。`stickyHeader` と `bodyDateBoundaries` を有効にし、#55 と同じ固定行見出し、列幅、横スクロール、日付境界線、本文スクロール中の見出し吸着を使う。初期列は現在を含む列（無ければ次の未来列）とし、全期間は横スクロールで読めるようにする。凡例は #55 と同じく詳細本文の先頭、表の直前に置き、項目は本情報固有の「高」「中」「なし」（文字なし黒セルの見本）「?（欠測・未取得）」とする。セルの `aria-label="高・中の表示なし"` は維持する。配置・間隔は #55 の既存凡例に合わせ、値と色の対応だけ本情報の規則を使う。専用表の `ew-table` や一段見出しを詳細に再利用しない。

共通部品の `TimeSeriesCell` に任意の `rowSpan?: number` を追加し、未指定時は既定1とする。遠距離の雨では大雨行の対応列セルに `rowSpan: 2` を付け、土砂災害行の同列セルは作らない。共通部品は上の行が占有する列を追跡して次行のセルを正しい列へ配置し、横方向の既存 `span`、`bodyDateBoundaries`、見出しと本文の列幅同期を維持する。大雨・土砂災害の行見出し自体は各行に一つずつ残す。縦結合が表の最終行を越える、不正な列数、先行セルと重なる入力は検証で検出する。既存 #55 の入力は `rowSpan` を渡さず、DOM 構造・スクロール・アクセシビリティの既存挙動を変えない。セル位置だけは本節末の UI 監修で明示的に補正する。

詳細の入口は既存の #61 共通ダイアログを利用する。見出しは「警報級の可能性」、対象は「東京地方」。詳細のヘッダー領域には「明後日まで」「明々後日以降」の二系列のラベルと時刻を併記し、表内には表示しない。既存 `DetailDialogMeta.time` は単一時刻なので、本パネル用の任意の `issuedTimes` 入力を追加して単一時刻の表示を置き換える。他ダイアログの `time` 表示は変更しない。どちらかの時刻が `null` の場合は、その系列について「未取得」「発表時刻不明」を示す。詳細を開けるのは保持値があるときだけとし、初回取得中の時刻ラベルは出さない。詳細が開いている間に系列状態が変わっても、ヘッダーは系列ごとに更新する。横幅を超える時間軸は横スクロールで全期間を読めるようにし、列・行見出しとセルの対応を視覚と読み上げの両方で識別できるようにする。パネルおよび詳細で「高」「中」は文字を消さず既存の意味色トークンで強調する。凡例は詳細に「高」「中」「なし」（文字なし黒セルの見本）「?（欠測・未取得）」を表示し、色だけに依存しない。色の HEX 値は直書きしない。

パネル・詳細のデータセルは `inline-size: 3rem` に統一し、文字の有無で幅を変えない。`rankValue='高'|'中'` は文字と既存の意味色を使う。`rankValue='なし'` と `condition='値なし'` は同じ `--md-sys-color-scrim` 背景の、バー・文字を置かない黒セルとする。両方とも読み上げは中立的な「高・中の表示なし」に統一する。入力 DTO 上の区別はモデル内部で保持し、表示や `aria-label` で気象上の意味の違いを示唆しない。HEX は直書きしない。`condition` に欠測が明示される場合、および提供対象の現象・区間に対する参照欠落は #55 の `.wts-cell-missing` を再利用した点線セルと `?` で示し、「なし」へ補完しない。現象の `Kind` / 項目自体が無い位置はセル状の色・枠・記号を描かず、表の構造上必要な空の `td` だけを置く。対象外であることは読み上げラベルで残す。`data=null` または `availability='unavailable'` はセルではなく表単位の取得不能表示にする。stale で保持値がある場合は #52 に従い装飾・警告色を付けず前回値を表示する。文字のない黒セルと有字セルは、同じ高さの箱の中央に内容を配置する。`td` は垂直中央、セル内は `align-items: center` と `justify-content: center` を使い、空セルだけ上寄りにならないようにする。黒セルには両入力形とも `aria-label="高・中の表示なし"` を付け、単独の `?` には「欠測」、対象外には「対象外」と付ける。

### 5.1 UI監修用の開発フィクスチャ

既存の `?panelFixture=` に `early-warning` を追加する。確認 URL は `http://localhost:5174/?panelFixture=early-warning`（端末選択後）。開発ビルドだけで有効にし、本番ビルドではこのクエリを無視する。カードと詳細は合成 `EarlyWarningResponse` を本番と同じ `EarlyWarningContent`・モデル・`DetailDialog`・`DetailTimeSeriesTable` に通して描画し、フィクスチャ専用の表や条件分岐で見た目を模造しない。カードまたは詳細に「確認用データ」と明示し、発表情報と誤認させない。既存の `all-content`、`mixed` 等の名前・表示は維持する。

フィクスチャ作成時の現在時刻を基準に、JST の現在を含む近距離区間と続く2区間を作る。日界をまたいでもパネルに3コマが現れるようにし、区間見出し「12-18」等の書式を実描画で確認する。遠距離は同じ JST 基準日の D+3 以降に複数日列を作る。時刻とセルの `refId` は実 DTO と同じ参照方法で対応付ける。主な合成値は次のように配置する。

| 現象 | 近距離の3コマ | 遠距離 |
| --- | --- | --- |
| 大雨 | `高`、`なし`、`condition="値なし"` | 「雨」を土砂災害との縦結合セルとして `中` 等 |
| 土砂災害 | `中`、参照欠落、`なし` | 大雨との結合セルに含める |
| 大雪 | `condition="値なし"`、`高`、欠測 | `なし` |
| 暴風（雪） | `なし`、`なし`、`なし` | `高` |
| 波浪 | 近距離では `Kind` 自体なし | 遠距離に `中` を置き、詳細の近距離側を無表示で確認 |
| 高潮 | 近距離・遠距離とも `Kind` 自体なし | 無表示と行省略を確認 |

この組合せで、パネルでは高・中を含む行だけが出て、同じ行に両入力形から生成した同一の文字なし黒セルと、点線 `?` を視認できる。詳細では「なし」だけの行、近距離に Kind のない波浪、遠距離の雨の `rowSpan=2` を確認できる。`condition="値なし"` は XML 属性に相当する入力としてのみ合成し、その気象上の原因・意味は推定しない。必要な入力の欠測は明示 condition、参照欠落は対応セルなしでそれぞれ作る。

この URL では警報級の可能性の実 API 呼出を行わず、他の情報パネルの通常動作に影響させない。既存 `InfoPanelColumn` のフィクスチャ解決だけでは `useEarlyWarning` のポーリングが残るため、開発ビルドかつ名前が `early-warning` の場合に限りそのポーリングを無効にする。別の fixture 名・クエリなし・本番ビルドでは従来どおり API を呼ぶ。
