# Issue #56 G5. 警報級の可能性パネル 設計書

## 1. 目的・範囲

`GET /api/weather/early-warning` の `near`（VPFD61）と `far`（VPFW60）を、東京地方の「警報級の可能性」パネルに結線する。パネルには二表、詳細ダイアログには通しの時間軸を表示する。対象は両会場とも東京地方。履歴、API・DB・共通 DTO の変更、他パネルの変更は含めない。製造ブランチの想定名は `feature/issue-56-early-warning-panel`。

## 2. 根拠と確定判断

- [基本設計](../basic-design.md) §5.9・§5.13、[取得方法レポート](../data-acquisition-report.md) §3.3、[#52 設計](issue-52-info-panel-layout.md) §5、[#33 設計](issue-33-warning-rest-apis.md) §3.5、[#61 設計](issue-61-detail-dialog.md) を参照する。型は `packages/shared/src/weatherApi.ts` の `EarlyWarningResponse`、実装は既存の `InfoPanelFrame` / `DetailDialog` / `DetailTimeSeriesTable` を使用する。
- 実電文の照合先は [VPFD61・VPFW60 提供サンプル](../../../docs/260907_weather-data/jmaxml_20260723_Samples/) および[公式解説資料](<../../../docs/260907_weather-data/jmaxml_20260826_Manual(pdf)/>)。リポジトリ内の `apps/api/tests/fixtures/jma/90_01_01_241031_VPFD61.xml` と `69_01_01_241031_VPFW60.xml` でも近距離の大雨・土砂災害と遠距離の雨、`高`・`中`・`なし`・`condition="値なし"` を確認できる。東京地方を対象にすることと重複日排除は取得方法レポートで検証済み。
- ユーザー決定（2026-09-28）: 凡例は文字と既存意味色を併用する。「なし」は `－`、「値なし」は空白とし、欠測・未取得は #227 の区別を踏襲する。stale は前回値を装飾せず表示する。パネルと詳細の固定行順は **大雨、土砂災害、大雪、暴風（雪）、波浪、高潮**。遠距離の「雨」は大雨・土砂災害の二行にまたがる一つのセルとして示す。二系列の発表時刻は表内ではなく、パネルおよび詳細のヘッダー領域に「明後日まで」「明々後日以降」と対応付けて併記する。
- 近距離と遠距離で現象の分類が異なる。たとえば近距離の大雨・土砂災害と遠距離の雨は同一現象へ変換しない。遠距離の雨を二つの値に複製することも禁止する。

## 3. データと時間軸

`near` / `far` の各 `WeatherDataset` を独立に扱い、`metadata.availability`、`issuedAt`、`data` を保持する。`timeDefines` の `timeId` と `cells.refId` は**同じ segment 内だけ**で照合し、配列添字や segment をまたぐ ID 一致で結合しない。列は `timeFrom` の昇順、同時刻なら `timeTo`、`sequence` の順とする。日付・時刻は JST で表示し、列見出しは提供区間の始終または日付を示す。固定コマ数で切り捨てない。

発表日を JST 日付で求め、近距離はその電文の提供区間を維持し、遠距離は発表日から数えて明々後日以降の列だけを表示する。遠距離電文に残る明後日の列は表示しない。近距離が未取得でもこの境界を遠距離の発表日から求める。異なる発表日の電文が混在したときは各 segment の発表日を基準にし、同一の実時間区間を二重に表示しない。両系列の同一区間が衝突した場合は近距離を優先し、遠距離の重複列を除く。重複のない全区間は閲覧可能にする。

表示名への対応は原文の既知の `phenomenonCode` / `phenomenonName` を明示的に対応付ける。近距離の大雨→大雨、土砂災害→土砂災害、雪→大雪、風（風雪）→暴風（雪）、波→波浪、潮位→高潮。遠距離の雨→大雨・土砂災害の結合セル、その他は同じ対応を使う。未知の現象を既知行に推測で割り当てない。未知現象が来た場合は原文名の追加行に表示し、提供値を失わない。既知行は値が片側だけでも固定順で表示するが、両側とも現象自体が無い行は省く。

## 4. パネルと詳細

パネル本文は「明後日まで」「明々後日以降」の二表とする。**両表とも行見出しは大雨、土砂災害、大雪、暴風（雪）、波浪、高潮の固定順**とする。近距離表では大雨・土砂災害を別々のセルで示す。遠距離表では原文の「雨」を大雨・土砂災害の二行を縦結合した一つのセルで示し、値を複製しない。各表の列構成と現象の原文はそれぞれの電文に由来し、二表を一つに混ぜない。各表に存在しない現象の行は省き、片側だけに存在する現象も表示する。片方だけ取得不能ならその表を描画せず、表の位置に「取得できませんでした」を表示し、もう片方の表は維持する。両方取得不能なら共通枠の失敗状態を使う。片方に正常な空データがある場合は「発表された値はありません」と示し、取得失敗と区別する。

共通枠 `InfoPanelFrame` の既存 `data` 状態は時刻一つを必須とするため、本パネルに限って、ヘッダーに系列別時刻を渡せる入力契約を追加する。たとえば `issuedTimes: { near: string | null; far: string | null }` をパネル固有のオプション入力とし、指定時は既存の単一時刻を描画しない。未指定の他パネルは現行の単一時刻表示を維持する。`InfoPanelColumn` の入力から `InfoPanelFrame` へ渡す型も必要な範囲だけ拡張する。ヘッダーは対象名「東京地方」の後に「明後日まで: 9/28 05:00発表」「明々後日以降: 9/28 11:00発表」のように二つを必ずラベル付きで並べる。発表時刻は各系列の `metadata.issuedAt` を用い、最新時刻で代表させない。表内・表直上には発表時刻を重複表示しない。狭い幅では折り返してよい。

時刻の `null` は省略せず、取得不能で保持値のない系列は「明後日まで: 未取得」のように表示する。取得済みデータの `issuedAt` が `null` の場合は「明後日まで: 発表時刻不明」と表示し、未取得と混同しない。stale で保持した時刻は前回値のまま通常の発表時刻として表示し、鮮度の装飾を付けない。初回 loading では各系列を「取得中」、両系列が取得不能の場合は両方を「未取得」と表示する。これらのラベルはパネルのヘッダー領域に置く。

詳細は一つの表とし、§3 の全列を時間順に並べる。行見出しはパネルの二表と同じ固定順を使う。大雨・土砂災害の近距離セルはそれぞれの値を表示する。遠距離の雨はパネルの遠距離表と同様、二行を縦に結ぶ一つのセル（`rowSpan=2` 相当）として描画し、その列に対して一回だけ読み上げられるよう「大雨・土砂災害、○日、雨の警報級の可能性、高」のようにラベルを付ける。近距離に片方だけ存在しても、詳細の行順と遠距離の結合は維持する。遠距離の雨が無い列は結合せず、各行の欠けた値を個別に扱う。

詳細の入口は既存の #61 共通ダイアログを利用する。見出しは「警報級の可能性」、対象は「東京地方」。詳細のヘッダー領域にもパネルと同じ二系列のラベルと時刻を併記し、表内には表示しない。既存 `DetailDialogMeta.time` は単一時刻なので、本パネル用の任意の `issuedTimes` 入力を追加して単一時刻の表示を置き換える。他ダイアログの `time` 表示は変更しない。片側の時刻が `null` の場合の「未取得」「発表時刻不明」はパネルと同じ規則とする。横幅を超える時間軸は横スクロールで全期間を読めるようにし、列・行見出しとセルの対応を視覚と読み上げの両方で識別できるようにする。パネルおよび詳細で「高」「中」は文字を消さず既存の意味色トークンで強調する。凡例は詳細に「高」「中」「－（なし）」「空白（値なし）」を表示し、色だけに依存しない。色の HEX 値は直書きしない。

セルは `rankValue='高'|'中'` を文字どおり、`rankValue='なし'` を `－`、`condition='値なし'` を空白で示す。`condition` に欠測が明示される場合、および提供対象の現象・区間に対する参照欠落は `?` とし、「なし」へ補完しない。現象自体がその segment に存在しない区間は対象外として空白と区別できる読み上げラベルを付ける。`data=null` または `availability='unavailable'` はセルではなく表単位の取得不能表示にする。stale で保持値がある場合は #52 に従い装飾・警告色を付けず前回値を表示する。画面表示の空白セルにも `aria-label="値なし"` を付け、単独の `?` には「欠測」、対象外には「対象外」と付ける。

## 5. 実装箇所と検証

`apps/web/src/map/panels/` 配下に本パネルのモデル、描画、スタイル、テストを追加する。系列別時刻をヘッダーに渡すため `InfoPanelFrame`、`InfoPanelColumn`、`DetailDialog` の入力と表示を本パネル用に最小限拡張し、既存パネルの単一時刻表示を維持する。`InfoPanelColumn` の `earlyWarning` 入力と結線する。既存の仮詳細入口のうち本パネル分だけ置き換える。ポーリングと端末 ID・本番/訓練の渡し方は #55 のパネル実装に合わせる。新しい共通色トークンや DTO は増やさない。既存未コミット変更は対象外とする。

受け入れ条件:

- [ ] AC-1: east / trc の双方で東京地方を対象に `GET /api/weather/early-warning` を呼び、`near` と `far` の独立した発表時刻・状態・値を表示する。本番/訓練の区別を維持する。
- [ ] AC-2: 近距離の区間、遠距離の明々後日以降を提供時間定義どおり全件表示し、明後日の重複列を除く。JST 日界前後、異なる発表日、逆順の timeDefines、同じ timeId が両系列にあるケースをテストする。
- [ ] AC-3: パネルは二表を維持し、表内に時刻を置かず、ヘッダーにラベル付きの二時刻を併記する。詳細も同じヘッダー表示とする。片側の時刻が null のとき、未取得は「未取得」、データ保持中で時刻不明は「発表時刻不明」、初回取得中は「取得中」と表示する。片側だけ取得不能・片側だけ stale・正常空・両側取得不能を独立に検証し、保持値の stale 装飾が無い。
- [ ] AC-4: パネルの二表と詳細の行順が指定の六見出しに一致する。近距離の大雨・土砂災害を別セルにし、パネルの遠距離表と詳細の遠距離列では雨を二行にまたがる単一セルにする。片側だけの現象も表示し、未知現象の値を失わない。
- [ ] AC-5: `高`・`中`・`なし`・`値なし`・欠測・対象外・表全体の未取得の表示と読み上げが区別できる。凡例は文字と意味色を併用し、HEX の直書きが無い。
- [ ] AC-6: 詳細を開閉し、横スクロールで全列へ到達できる。#61 のフォーカスと右列スクロール復帰を維持する。幅が小さい表示でも行見出しとセルの対応を失わない。
- [ ] AC-7: `npm run lint`、`npm run typecheck`、`npm run format:check`、`npm run test -w apps/web` が成功し、変更範囲が本 Issue に限られる。

## 6. AD-H049 の結論と保留

二系列の独立した状態・発表時刻を維持し、パネルは二表、詳細は重複日を除いた通しの時間軸とする。両者で固定の六見出しを使い、遠距離の雨は大雨・土砂災害の結合セルにして値を二重化しない。`なし`・`値なし`・欠測・未取得を別状態として扱う。これを AD-H049 の G5 結論とする。二系列の時刻をパネル・詳細のヘッダーに併記し、単一代表時刻を選ばない。見た目の細部と実機での最終視認性は製造後の画面検収で判断する。
