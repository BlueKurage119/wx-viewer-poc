# Issue #56 G5. 警報級の可能性パネル 設計書

## 1. 目的・範囲

`GET /api/weather/early-warning` の `near`（VPFD61）と `far`（VPFW60）を、東京地方の「警報級の可能性」パネルに結線する。パネルには近距離の現在を含む直近3コマ、詳細ダイアログには近距離・遠距離を通した時間軸を表示する。対象は両会場とも東京地方。履歴、API・DB・共通 DTO の変更、他パネルの変更は含めない。製造ブランチの想定名は `feature/issue-56-early-warning-panel`。

## 2. 根拠と確定判断

- [基本設計](../basic-design.md) §5.9・§5.13、[取得方法レポート](../data-acquisition-report.md) §3.3、[#52 設計](issue-52-info-panel-layout.md) §5、[#33 設計](issue-33-warning-rest-apis.md) §3.5、[#61 設計](issue-61-detail-dialog.md) を参照する。型は `packages/shared/src/weatherApi.ts` の `EarlyWarningResponse`、実装は既存の `InfoPanelFrame` / `DetailDialog` / `DetailTimeSeriesTable` を使用する。
- 実電文の照合先は [VPFD61・VPFW60 提供サンプル](../../../docs/260907_weather-data/jmaxml_20260723_Samples/) および[公式解説資料](<../../../docs/260907_weather-data/jmaxml_20260826_Manual(pdf)/>)。リポジトリ内の `apps/api/tests/fixtures/jma/90_01_01_241031_VPFD61.xml` と `69_01_01_241031_VPFW60.xml` でも近距離の大雨・土砂災害と遠距離の雨、`高`・`中`・`なし`・`condition="値なし"` を確認できる。東京地方を対象にすることと重複日排除は取得方法レポートで検証済み。
- ユーザー決定（2026-09-28）: 凡例は文字と既存意味色を併用する。「なし」は `－`、「値なし」は空白とし、欠測・未取得は #227 の区別を踏襲する。stale は前回値を装飾せず表示する。パネルと詳細の固定行順は **大雨、土砂災害、大雪、暴風（雪）、波浪、高潮**。遠距離の「雨」は大雨・土砂災害の二行にまたがる一つのセルとして示す。発表時刻は表内には置かず、パネルのヘッダーには「明後日まで」だけ、詳細のヘッダーには二系列を対応付けて表示する。
- UI監修による変更（2026-09-28、ユーザー確定）: [基本設計](../basic-design.md) §5.9 の【確定】「パネル内は二表」に代えて、パネルは「明後日まで」の現在を含む直近3コマだけを表示する。その3コマに `高` または `中` がある行だけを表示し、`なし` は行抽出に含めない。「明々後日以降」は詳細だけで閲覧する。基本設計本文は本 Issue で改訂しないため、統括担当へ差分を引き継ぐ。
- 近距離と遠距離で現象の分類が異なる。たとえば近距離の大雨・土砂災害と遠距離の雨は同一現象へ変換しない。遠距離の雨を二つの値に複製することも禁止する。

## 3. データと時間軸

`near` / `far` の各 `WeatherDataset` を独立に扱い、`metadata.availability`、`issuedAt`、`data` を保持する。`timeDefines` の `timeId` と `cells.refId` は**同じ segment 内だけ**で照合し、配列添字や segment をまたぐ ID 一致で結合しない。列は `timeFrom` の昇順、同時刻なら `timeTo`、`sequence` の順とする。日付・時刻は JST で表示し、列見出しは提供区間の始終または日付を示す。詳細では固定コマ数で切り捨てない。パネルに限り §4 の3コマ表示を適用する。

発表日を JST 日付で求め、近距離はその電文の提供区間を維持し、遠距離は発表日から数えて明々後日以降の列だけを表示する。遠距離電文に残る明後日の列は表示しない。近距離が未取得でもこの境界を遠距離の発表日から求める。異なる発表日の電文が混在したときは各 segment の発表日を基準にし、同一の実時間区間を二重に表示しない。両系列の同一区間が衝突した場合は近距離を優先し、遠距離の重複列を除く。重複のない全区間は閲覧可能にする。

表示名への対応は原文の既知の `phenomenonCode` / `phenomenonName` を明示的に対応付ける。近距離の大雨→大雨、土砂災害→土砂災害、雪→大雪、風（風雪）→暴風（雪）、波→波浪、潮位→高潮。遠距離の雨→大雨・土砂災害の結合セル、その他は同じ対応を使う。未知の現象を既知行に推測で割り当てない。未知現象が来た場合は原文名の追加行に表示し、提供値を失わない。既知行は値が片側だけでも固定順で表示するが、両側とも現象自体が無い行は省く。

## 4. パネルと詳細

パネル本文には `near`（明後日まで）だけを表示し、`far`（明々後日以降）の表・時刻・状態を置かない。現在時刻を含む区間（`timeFrom <= now < timeTo`）を起点に、時間順の次の2区間まで最大3コマを選ぶ。現在を含む区間がなければ、未来の最初の区間から最大3コマとする。未来の区間もなければ「表示できる時間帯はありません」と示し、保持済みの全期間は詳細で閲覧できる。境界 `now=timeTo` は次の区間に属する。`now` は一回だけ取得し、列選択と行抽出に同じ値を使う。パネルに横スクロールは設けない。

パネルの行見出しは **大雨、土砂災害、大雪、暴風（雪）、波浪、高潮** の順とし、選択した最大3コマ内に `rankValue='高'` または `'中'` が一つ以上ある行だけを表示する。対象外の行と、`なし`・値なし・欠測だけの行はパネルから省く。表示対象になった行の3コマでは `なし` を `－`、値なしを空白、欠測を `?` として維持する。選択したコマに該当行が一つもなければ「警報級の可能性はありません」と示す。未知現象も同じ抽出規則で、該当すれば既知の六行の後に原文名で表示する。`far` にだけ `高`・`中` があってもパネルの行を増やさない。パネルの詳細入口は行の有無に関係なく残す。

共通枠 `InfoPanelFrame` は本パネルに限り、ヘッダーに「明後日まで: 9/28 05:00発表」のような近距離のラベル付き時刻を表示できる入力を設ける。既存 `data` 状態の単一時刻から機械的に出す時刻は重複表示しない。他パネルの時刻表示は現行どおりとする。`near.metadata.issuedAt` が `null` でデータがあるときは「明後日まで: 発表時刻不明」、保持値のない取得不能時は「明後日まで: 未取得」、初回取得中は「明後日まで: 取得中」とする。stale の保持時刻は装飾なしで表示する。`far` だけ取得できても、パネルは近距離の未取得状態を表示し、遠距離の値を代用しない。パネルの本文・ヘッダーには遠距離の時刻や取得状態を重複表示せず、詳細で扱う。

詳細は一つの表とし、§3 の全列を時間順に並べる。行見出しはパネルと同じ固定順を使い、詳細では `高`・`中` の有無によって行を絞らない。大雨・土砂災害の近距離セルはそれぞれの値を表示する。遠距離の雨は、二行を縦に結ぶ一つのセル（`rowSpan=2` 相当）として描画し、その列に対して一回だけ読み上げられるよう「大雨・土砂災害、○日、雨の警報級の可能性、高」のようにラベルを付ける。近距離に片方だけ存在しても、詳細の行順と遠距離の結合は維持する。遠距離の雨が無い列は結合せず、各行の欠けた値を個別に扱う。

詳細の入口は既存の #61 共通ダイアログを利用する。見出しは「警報級の可能性」、対象は「東京地方」。詳細のヘッダー領域には「明後日まで」「明々後日以降」の二系列のラベルと時刻を併記し、表内には表示しない。既存 `DetailDialogMeta.time` は単一時刻なので、本パネル用の任意の `issuedTimes` 入力を追加して単一時刻の表示を置き換える。他ダイアログの `time` 表示は変更しない。どちらかの時刻が `null` の場合は、その系列についてパネルと同じ「未取得」「発表時刻不明」「取得中」の規則を適用する。詳細が開いている間に系列状態が変わっても、ヘッダーは系列ごとに更新する。横幅を超える時間軸は横スクロールで全期間を読めるようにし、列・行見出しとセルの対応を視覚と読み上げの両方で識別できるようにする。パネルおよび詳細で「高」「中」は文字を消さず既存の意味色トークンで強調する。凡例は詳細に「高」「中」「－（なし）」「空白（値なし）」を表示し、色だけに依存しない。色の HEX 値は直書きしない。

セルは `rankValue='高'|'中'` を文字どおり、`rankValue='なし'` を `－`、`condition='値なし'` を空白で示す。`condition` に欠測が明示される場合、および提供対象の現象・区間に対する参照欠落は `?` とし、「なし」へ補完しない。現象自体がその segment に存在しない区間は対象外として空白と区別できる読み上げラベルを付ける。`data=null` または `availability='unavailable'` はセルではなく表単位の取得不能表示にする。stale で保持値がある場合は #52 に従い装飾・警告色を付けず前回値を表示する。画面表示の空白セルにも `aria-label="値なし"` を付け、単独の `?` には「欠測」、対象外には「対象外」と付ける。

## 5. 実装箇所と検証

`apps/web/src/map/panels/` 配下に本パネルのモデル、描画、スタイル、テストを追加する。近距離のラベル付き時刻をパネルヘッダーへ、二系列の時刻を詳細ヘッダーへ渡すため `InfoPanelFrame`、`InfoPanelColumn`、`DetailDialog` の入力と表示を本パネル用に最小限拡張し、既存パネルの単一時刻表示を維持する。`InfoPanelColumn` の `earlyWarning` 入力と結線する。既存の仮詳細入口のうち本パネル分だけ置き換える。ポーリングと端末 ID・本番/訓練の渡し方は #55 のパネル実装に合わせる。新しい共通色トークンや DTO は増やさない。既存未コミット変更は対象外とする。

受け入れ条件:

- [ ] AC-1: east / trc の双方で東京地方を対象に `GET /api/weather/early-warning` を呼び、`near` と `far` の独立した発表時刻・状態・値を保持し、詳細で確認できる。本番/訓練の区別を維持する。
- [ ] AC-2: 詳細では近距離の区間、遠距離の明々後日以降を提供時間定義どおり全件表示し、明後日の重複列を除く。JST 日界前後、異なる発表日、逆順の timeDefines、同じ timeId が両系列にあるケースをテストする。
- [ ] AC-3: パネルには近距離の現在を含む区間と次の2区間（不足時はある分だけ）を表示し、遠距離の表・時刻・状態を表示しない。現在区間がないときは未来の先頭から選び、未来もないときは本文に「表示できる時間帯はありません」を表示する。境界 `now=timeTo`、3コマ未満、過去だけの保持値をテストする。
- [ ] AC-4: パネルには選択した3コマ内で `高` / `中` のある行だけを六見出しの固定順で出す。`なし` だけの行、値なし・欠測だけの行、遠距離だけが `高` / `中` の行は出ない。表示対象行内の `なし` は `－` のまま残る。該当行0件の文言と、行がなくても詳細入口が残ることを確認する。
- [ ] AC-5: パネルヘッダーは近距離の発表時刻だけをラベル付きで示す。詳細ヘッダーは二系列の時刻をラベル付きで示す。表内に発表時刻の重複がない。系列ごとの時刻 null・初回取得中・保持値なし・stale を確認し、遠距離だけ取得できた場合もパネルが遠距離値に置き換わらない。
- [ ] AC-6: 詳細には近距離・遠距離の全対象列と六見出しを表示し、`高` / `中` がない行も残す。近距離の大雨・土砂災害を別セルにし、遠距離の雨を二行にまたがる単一セルにする。片側だけの現象と未知現象も表示する。
- [ ] AC-7: `高`・`中`・`なし`・`値なし`・欠測・対象外・表全体の未取得の表示と読み上げが区別できる。凡例は文字と意味色を併用し、HEX の直書きが無い。
- [ ] AC-8: 詳細を開閉し、横スクロールで全列へ到達できる。#61 のフォーカスと右列スクロール復帰を維持する。幅が小さい表示でも行見出しとセルの対応を失わない。
- [ ] AC-9: `npm run lint`、`npm run typecheck`、`npm run format:check`、`npm run test -w apps/web` が成功し、変更範囲が本 Issue に限られる。

## 6. AD-H049 の結論と保留

二系列の独立した状態・発表時刻を維持し、パネルは近距離の直近3コマとその中に `高`・`中` のある行だけ、詳細は近距離・遠距離の重複日を除いた通しの時間軸と全行を表示する。パネル・詳細で固定の六見出しを使い、詳細の遠距離の雨は大雨・土砂災害の結合セルにして値を二重化しない。`なし`・`値なし`・欠測・未取得を別状態として扱う。これを AD-H049 の G5 結論とする。パネルヘッダーには近距離だけ、詳細ヘッダーには二系列の時刻を示し、単一代表時刻を選ばない。基本設計 §5.9 の二表パネル方針は2026-09-28のユーザー判断で変更された。見た目の細部と実機での最終視認性は製造後の画面検収で判断する。
