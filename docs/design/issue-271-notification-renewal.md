## 3. 自動確認設定

### 3.1 照合と保存境界

【統括推奨】設定は `messageDefinition.id` の集合とする。版は照合に含めず、文言の改訂後も同一定義の指定を維持する。カテゴリが `warning` でない通知には、同じ ID が登録されていても適用しない。`messageDefinition === null`・未知の ID は非対象とし、本文の文字列一致で補完しない。

【統括推奨】新規ブラウザでの指定は空集合（全て非対象）。自動確認までの時間は今回は固定 5,000ms とし、時間設定 UI は追加しない。設定変更は以後の新規受信に適用し、受信済みの表示色・音・タイマーは変更しない。これにより、設定操作だけで表示中の通知が突然消えることを避ける。

【統括推奨】`localStorage` の `wx-viewer:notification-preferences:v1` に保存する。同一ブラウザ・同一オリジン内で共通とし、端末 ID ごとの分離や他タブへの即時同期は今回設けない。【統括推奨・承認対象】使用中の設定と編集中の設定（draft）を分離し、保存成功時だけ使用中の設定へ反映してダイアログを閉じる。保存失敗時はそのセッションで従来使用していた旧設定を維持する（draft は適用しない）。ダイアログは開いたまま、draft と「設定を保存できません。再試行してください。」というエラーを保持して再試行できるようにする。JSON 破損・未知のスキーマ版は空集合へ縮退し、通知配信を停止しない。

```ts
interface NotificationPreferences {
  readonly schemaVersion: 1;
  readonly autoConfirmMessageDefinitionIds: readonly string[];
}

interface NotificationPreferencesRepository {
  load(): NotificationPreferences;
  save(value: NotificationPreferences): { readonly saved: boolean };
}

interface WarningPresentationPolicy {
  readonly autoConfirmAfterMs: 5000 | null;
  readonly tone: 'level2' | 'level3';
}

function resolveWarningPresentationPolicy(
  item: NotificationFeedItem,
  preferences: NotificationPreferences,
): WarningPresentationPolicy | null;
```

`resolveWarningPresentationPolicy` は警報以外に `null` を返す。対象は Lv.2、非対象は Lv.3 とする。保存処理は表示コンポーネントに埋め込まず、repository に閉じ込める。設定は起動時の初回受信より前に同期的に読み込み、保存済み設定の読み込み待ちで最初の一件だけ非対象になる状態を作らない。将来のクラウド化では非同期化・認証・同期競合を別途設計し、今回サーバー API は追加しない。

### 3.2 設定画面と入口

【確定】警報一覧のフィルター付近から設定ダイアログを開く。【設計案】入口は「通知設定」ボタンとし、ダイアログでメッセージ定義ごとのチェックを編集して保存する。警報カテゴリを許可する定義だけを一覧化し、定義タイトルを表示する。気象・システムの区分を付け、未受信の定義も設定できるようにする。【統括推奨・承認対象】保存成功時は設定を適用して閉じることを結果とし、成功メッセージの常設は行わない。保存失敗時は閉じずに draft とエラーを保持し、再試行できるようにする。取消・Escape は draft を破棄して閉じ、旧使用中設定を維持する。

定義のタイトルが同じ場合は、定義 ID に対応する日本語の補助表示を併記して識別する。例えば `system-weather-acquisition-report-stale` と `system-weather-delivery-report-stale` は同じタイトルなので、それぞれ「気象取得Worker」「気象情報提供Worker」を併記する。`origin` とタイトルだけで区別できるとは仮定しない。

定義表そのものを表示層へ公開せず、shared に次のメタデータ取得口を追加する案とする。

```ts
interface WarningMessagePreferenceOption {
  readonly id: NotificationMessageDefinitionId;
  readonly title: string;
  readonly qualifier: string | null;
  readonly origin: NotificationOrigin;
}
function listWarningMessagePreferenceOptions(): readonly WarningMessagePreferenceOption[];
```

【設計案】既存の「検索」「条件クリア」とは別の操作群として近傍に配置する。`WarningListView` でフィルターのフォームと設定入口を兄弟要素にする案を推奨し、ボタンは `type="button"` とする。入口・ダイアログの操作で検索フォームを submit せず、編集中の検索条件（draft）、適用済み条件（applied）、検索エラーを変更しない。ダイアログも検索フォームの外に置き、Enter による設定操作が検索へ伝播しない構成にする。

設定一覧は定義メタデータを情報源とし、一覧の検索結果・件数・通知履歴・検索条件の妥当性には依存させない。初回受信前、検索結果ゼロ件、検索エラー中でも開け、未受信の定義も設定できる。入口は警報一覧に置くが、設定の適用範囲は引き続き全ビュー共通の通知処理である。

ダイアログを開いたら内部へフォーカスを移し、開いている間は内部でキーボード操作できるようにする。保存成功・取消・Escape による終了後は入口ボタンへフォーカスを戻す。保存失敗時はダイアログ内にフォーカスを保つ。取消・Escape では保存失敗後を含め未保存の draft とエラーを破棄し、使用中設定を変更しない。具体的な余白・折り返し位置は実画面検証で調整する。「通知設定」というボタン名と配置の詳細は本書の設計案であり、ユーザーの個別指定ではない。

この配置は通知の履歴確認と設定を近い場所で行え、下部通知領域の横幅も維持できる。一方、他ビューから設定する場合は警報一覧への移動が必要になる。

## 4. 状態遷移とタイマー

### 4.1 受信期限モデル

【確定】自動確認対象の各警報をクライアントの通知 store が初めて受信した時点から 5 秒で自動確認する。電文の発生時刻 `occurredAt`・検知時刻 `detectedAt` は起点にしない。表示累計時間方式は採用しないため、表示前に期限を迎えた一件も確認済みになる。

【設計案】新規 `feedKey` の受信時に設定から表示方針を決め、`receivedAtMs + 5000` を一件ごとの期限として保持する。重複受信・表示切替・設定保存で期限を作り直さない。時刻は注入可能な `Date.now()` 相当の時計を使用し、ブラウザ停止中も壁時計上の期限を維持する。OS の時刻補正に対する別途の時刻同期は今回追加しない。

```ts
interface WarningPresentationState {
  readonly policy: WarningPresentationPolicy;
  readonly autoConfirmDeadlineMs: number | null;
}
type ConfirmationCause = 'manual' | 'automatic';

function confirmNotification(
  state: NotificationUiState,
  feedKey: string,
  mode: TerminalMode,
  cause: ConfirmationCause,
): NotificationUiState;

function advanceAutoConfirmation(
  state: NotificationUiState,
  mode: TerminalMode,
  nowMs: number,
): {
  readonly state: NotificationUiState;
  readonly automaticallyConfirmedFeedKeys: readonly string[];
};
```

`NotificationUiState` に `warningPresentationByFeedKey: Readonly<Record<string, WarningPresentationState>>` を追加する。非対象警報も音・配色の方針を保持し、期限は `null` とする。問いかけ・非常には期限を作らない。

### 4.2 遷移と副作用

- 受信時: 初回受信時刻と表示方針を同じイベントで記録する。通常の表示・鳴動要求を行い、対象警報には 5 秒後の期限を設定する。
- 表示待ち・警報行の割り込み・問いかけや非常の音の割り込み: 期限を変更しない。画面に表示される一件だけでなく、全ての期限到達済み対象警報を確認する。
- 非表示タブ: タイマーを停止する仕様にはしない。ブラウザのタイマー抑制等で実行が遅れた場合は、復帰時の `visibilitychange` で現在時刻と期限を照合し、期限到達済みをまとめて確認する。受信処理と確認処理の直前にも期限を照合する。確認処理では未確認全体から鳴動候補を選び直さない。
- H 端末で非表示の system 通知: 【設計案】受信済みの対象警報であれば同じ期限でフロント状態を確認済みにする。表示・鳴動は従来どおり行わず、確認による音の停止にも関与させない。期限進行と端末による表示フィルターを独立させ、サーバー側の通知や履歴は変更しない。
- 時間満了: `automatic` 原因で確認済みにし、当該行は次の未確認または空欄を表示する。確認音・完了メッセージ・後続の再鳴動は出さない。
- 手動確認・端末切替・アンマウント: 対象のタイマーを解除する。旧セッションのコールバックは世代識別または cleanup で無効にし、別セッションの同名 `feedKey` を誤確認しない。満了と手動確認の競合は冪等に処理する。

タイマーは最も近い未確認の期限へ一つ設定し、発火時に全期限を走査して次回を予約する。ブラウザ実行中は期限に従って処理し、ブラウザが実行を抑制した区間について「現実時間の 5 秒ちょうどで UI が更新される」とは保証しない。確認済み・期限・受信済み通知は保存対象にせず、再起動時の新規受信は新たな 5 秒の起点となる。

状態更新と鳴動停止は同じ結果の `automaticallyConfirmedFeedKeys` と各通知の受信時に記録したレベルを使って連携する。停止比較の対象は今回新たに確認された通知のうち `isVisibleForTerminal(item, mode)` が真の一件だけとし、鳴動元との feedKey 一致ではなく、§5 のレベル比較で停止を判断する。非表示通知は確認状態だけ更新し、可視通知の音を停止しない。reducer 内で音を操作せず、受信 hook の状態参照と React state の両方に同じ遷移を反映して、連続受信による期限の取りこぼしを防ぐ。

**既存確認関数への注意:** 現在は警報を確認しても `selectedQuestionFeedKey` と `selectedQuestionChoice` を無条件に消す。自動確認ではこの副作用を除外し、別行で選択中の問いかけ・非常の回答を保持する。`automatic` は対象警報だけに許可し、未知の `feedKey` や確認済みへの呼び出しは状態を変えない。

## 5. 鳴動との連携

### 5.1 音源と新着の優先順位

【確定】B 案を採用し、優先順位を非常（Lv.5）> 問いかけ（Lv.4）> 非対象警報（Lv.3）> 対象警報（Lv.2）とする。

| 区分 | 音源 | 自動確認 |
| --- | --- | --- |
| 対象警報 | `/audio/2.wav` | 受信から 5 秒で確認 |
| 非対象警報 | `/audio/3.wav` | しない |
| 問いかけ | `/audio/4.wav` | しない |
| 非常 | `/audio/5.wav` | しない |

【確定】新着は新規の `feedKey` で重複排除した今回受信分だけを指す。鳴動候補はその中の端末表示対象から最大レベルを選び、同レベル内は現行の新しい通知優先とする。停止中に新着を受信した場合、古い未確認の非常等へ戻らず、その新着候補の音を鳴らす。鳴動中は現在より高いレベルの新着だけが割り込み、同レベル以下の新着では既存の音を継続する。

【設計案】音は現行どおりループ再生する。`ChimeRequest` に `level: 2 | 3 | 4 | 5` を追加し、category だけでなく受信時に固定した表示方針から音源を決める。ブザー状態も現在レベルを保持する。`feedKey` は鳴動開始の契機を識別するために残すが、確認による停止を同一 feedKey に限定しない。

```ts
type ChimeLevel = 2 | 3 | 4 | 5;
interface ChimeRequest {
  readonly category: ChimeCategory;
  readonly feedKey: string;
  readonly level: ChimeLevel;
}
interface HeaderBuzzerState {
  readonly category: ChimeCategory | null;
  readonly feedKey: string | null;
  readonly level: ChimeLevel | null;
}
function selectNewArrivalChime(
  newItems: readonly NotificationFeedItem[],
  state: NotificationUiState,
  mode: TerminalMode,
): ChimeRequest | null;
function confirmationSoundDecision(
  currentLevel: ChimeLevel | null,
  confirmedLevel: ChimeLevel,
): 'stop' | 'keep';
```

`confirmationSoundDecision` を呼ぶ前に、確認前後の差分から今回新たに確認済みになった一件だけを取り出し、`isVisibleForTerminal(item, mode)` で絞り込む。未知・既確認・端末非表示の通知については helper を呼ばず、音に関与させない。

`confirmationSoundDecision` は、無音中（`currentLevel === null`）なら `keep`、同じレベルなら `stop`、異なるレベルなら高低によらず `keep` を返す。確認済み状態の更新と音の停止は独立し、音を維持する場合も操作対象の確認は成立する。

### 5.2 明示停止と確認による停止

【確定】F8 等の明示停止は、未確認が残っていても全消音する。確認状態は変更せず、次の新着まで鳴らさない。手動・自動確認、表示切替、タブ復帰、ブラウザの音再生リトライを契機に古い未確認を再鳴動させない。停止時に再生失敗の保留要求も解除する。

【確定】手動・自動確認の停止規則は共通とする。【設計案】レベル比較の対象は「今回新たに確認された通知、かつ `isVisibleForTerminal` が真」に限定し、端末の表示・鳴動範囲を維持する。H 端末で非表示の system 通知は確認状態のみ更新し、同じレベルの weather 通知が鳴動中でも音を止めない。

- 確認した一件のレベルが現在鳴動中のレベルより低い場合は、現在の音を維持する。
- 現在鳴動中と同じ最上レベルに属する通知を一件確認すれば停止する。表示中の `feedKey` と鳴動開始の `feedKey` が異なっても同レベルなら停止する。
- 停止後は、同レベル・下位の未確認が残っていても次の新着まで再鳴動しない。確認済みにするのは操作対象の一件だけで、残りの未確認は保持する。
- 無音中の確認では音を開始しない。従来の手動確認後の `nextUnconfirmedChime` による後続再鳴動・鳴り下がりを廃止する。

例: Lv.2 の A の鳴動中に Lv.3 の B が新着すると B が割り込む。その後 A を自動確認しても Lv.3 は継続する。さらに同じ Lv.3 の C が表示された場合、C を確認すれば鳴動元 B と別件でも停止し、B は未確認のまま残る。「同レベル全件の確認が終わるまで鳴らす」方式は採用しない。

自動確認対象は Lv.2 に限定されるため、現在 Lv.2 なら期限到達した対象一件の確認で停止し、現在 Lv.3〜Lv.5 なら音を維持する。同時満了は全対象を確認済みにしたうえで、今回新たに確認された可視通知だけに同じレベル規則を適用し、後続候補は選ばない。非表示通知しか満了していない場合は音を維持する。ブラウザに音再生を阻止された場合の操作時リトライは、現在も有効な未停止の要求だけに限る。

### 5.3 停止後の新着と古い高位通知の確認

【確定】停止後に届いた通知の音は、異なるレベルの古い通知への確認では停止しない。非常を F8 等で明示停止し、その後の新着 Lv.3 が鳴動している状態で古い非常を確認しても、Lv.3 の音を継続する。古い非常は確認済みになるが、音は現在鳴動中と同レベルの一件を確認するか、明示停止するまで継続する（より高位の新着による割り込みは §5.1 に従う）。

この判断は「同レベルの確認だけで停止」を採用したものであり、「確認した通知が現在レベル以上なら停止」にはしない。同レベルなら鳴動開始の feedKey と異なる一件の確認でも停止する既存合意、および今回新たに確認された可視通知だけを停止比較対象とする条件は維持する。

### 6.1 下部通知領域

### 6.2 操作ボタン

【設計案】`components/md` の `GbButton` ラッパーを使用し、ツールバーと同様の塗り・角形・文字・選択色・無効色にする。通知側に小さな `NotificationActionButton` を置いて既存スタイルの規則を合わせ、監視ツールバー全体の構造変更はしない。

- 警報の確認は一段階、問いかけ・非常は「確認」を選択して「送信」の二段階を維持する。
- 「詳細」は現状どおり無効とし、詳細画面の新規実装は含めない。

## 8. 受け入れ条件

以下は製造・検収時のチェックリスト。受信期限は注入時計で検証し、実ブラウザでは復帰時の期限照合も確認する。

- [ ] 警報一覧の検索条件を編集中に、フィルター付近の通知設定をクリックおよびキーボードで開く。検索 submit が発生せず、draft・applied・検索結果が設定操作により変更されない。
- [ ] 初回受信前、検索結果ゼロ件、検索エラー中に設定を開く。いずれも同じ定義一覧を編集でき、未受信の定義も指定できる。
- [ ] ダイアログを保存成功・取消・Escape でそれぞれ閉じる。入口ボタンへフォーカスが戻り、取消・Escape では未保存の変更が反映されない。ダイアログ内の Enter 操作で一覧検索が実行されない。
- [ ] 対象定義を保存後、ページを再読込し、同一定義の新しい `feedKey` の警報を投入する。対象として表示され、設定が引き継がれる。
- [ ] 設定一覧で同名の取得Worker／提供Workerの定義を表示する。日本語の補助表示で対象を区別でき、片方だけを指定したとき、その定義 ID のみが保存される。
- [ ] 非対象定義・定義なし・未知の定義の警報を投入する。5 秒経過後も自動確認されない。
- [ ] 登録済み定義を持つ問いかけ・非常を投入する。5 秒経過後も確認されず、二段階操作が必要である。
- [ ] 対象警報を受信して注入時計を 4,999ms 進め、まだ確認済みでないことを確認する。受信から 5,000ms 到達で当該一件が確認済みとなり、次の通知または空欄が表示される。
- [ ] 対象警報 A を受信し、2 秒後に警報 B で表示を割り込ませる。A は非表示でも最初の受信から 5 秒で確認済みになる。期限前に A を重複受信しても期限が延長されない。表示されないまま待機した対象も同じ期限で確認される。
- [ ] 問いかけを別行に表示し「確認」を選択した状態で警報を自動確認する。問いかけの選択・送信可能状態が保持される。
- [ ] 対象警報の受信直後にタブを非表示にし、タイマー実行を抑制して 5 秒以降に復帰させる。復帰時に期限切れが確認済みとなり、再鳴動しない。H 端末で非表示の system 対象警報も同じ受信期限で確認済みになるが、表示・鳴動は発生しない。
- [ ] H 端末で非表示の system Lv.2 を受信し、2 秒後に可視 weather Lv.2 を受信して鳴動させる。先の system の期限到来ではその確認状態だけが更新され、weather の音は継続する。後の weather の期限到来では停止する。既確認の通知へ確認を再実行しても音に影響しない。
- [ ] 手動確認・端末切替・アンマウント後に旧タイマーを進める。別の通知が誤って確認されず、再確認や余分な鳴動が起きない。
- [ ] 別々の受信試行で対象警報は `2.wav`、非対象警報は `3.wav` を要求する。問いかけ `4.wav`、非常 `5.wav` と区分優先順位は維持される。
- [ ] Lv.2 の A の鳴動中に Lv.3 の B を投入する。B が割り込み、A の自動確認後も B は継続する。Lv.3 中の Lv.2、同レベルの新着では音を差し替えない。
- [ ] 対象・非対象の警報を同じ応答で受信する。Lv.3 が選ばれ、問いかけ・非常も同時に含む場合は Lv.5 > Lv.4 > Lv.3 > Lv.2 となる。
- [ ] 鳴動元 B と別の同レベル通知 C を表示して C 一件を手動確認する。音は停止し、B を含む残りは未確認のまま保持される。下位へ鳴り下がらず、新着まで停止が続く。
- [ ] Lv.2 の一件が鳴動中に、別の Lv.2 対象を自動確認する。feedKey が異なっても停止する。Lv.3〜Lv.5 の鳴動中に Lv.2 を自動確認しても音は維持される。
- [ ] F8 等で非常を明示停止し、古い非常を未確認のまま残す。手動・自動確認、表示切替、タブ復帰では再鳴動せず、Lv.3 の新着だけを投入すると古い非常ではなく Lv.3 が鳴る。重複受信は新着に数えない。
- [ ] 再生失敗後に明示停止し、次のユーザー操作で再生リトライが起きないことを確認する。停止前の有効な要求に限ってリトライされる。
- [ ] 同時に期限へ到達する複数の Lv.2 対象を投入する。全件が確認済みとなり、Lv.2 鳴動中なら一度だけ停止、より高位の鳴動中なら継続する。
- [ ] 古い非常を F8 等で明示停止→新着 Lv.3 鳴動→古い非常を確認する操作を実行する。古い非常だけが確認済みになり、Lv.3 の音は継続する。続いて可視の Lv.3 一件を確認すると停止し、残り未確認は保持される。
- [ ] 受信済み A の後に設定を変更して新規 B を受信する。A の方針・期限は不変、B のみ新設定が適用される。同一定義の版変更でも指定が維持され、初期設定では全警報が非対象となる。
