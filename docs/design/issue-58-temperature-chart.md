# Issue #58 追補: 地域時系列予報 詳細ダイアログの気温折れ線グラフ 設計書

## 1. 目的・範囲

地域時系列予報（#58/#59、[設計書](issue-58-59-area-forecast-panel.md)）の詳細ダイアログで、気温の数値行を気温の折れ線グラフ行（各点に数値ラベル）に置き換える。製造ブランチは `feature/issue-58-temperature-chart`。

対象外（変更しない）: パネル（`AreaForecastContent.tsx` のパネル表。気温の数値行を含む）、parser・DB・API・`packages/shared`、朝の最低／日中の最高気温、#55・#56 の表示、#57 アメダスの表示と挙動、共用部品 `apps/web/src/map/detail/`。

## 2. 根拠と確定判断

### 2.2 確定事項（オーナー、2026-09-29）

1. グラフは詳細ダイアログだけに表示する。パネルは変更しない。
2. 気象庁HPの図と同じく、詳細の表に気温グラフの行を置き、各時点の列の真下に点を置く。表と一緒に横スクロールする。
3. 詳細の表から気温の数値行を削除し、グラフの各点に数値ラベル（例「15」。単位は見出しで示す）を添える。詳細の表は「天気」「風（m/s）」「気温（℃）」（グラフ）の3行。読み上げ（各時点の日時と気温、欠測）はグラフ行で満たす。パネルの気温数値行は変更しない。
4. 朝の最低・日中の最高気温の線は見送る（parser・DB・API は変更しない）。
5. 線と点の色は `--md-sys-color-primary`（#57 と同じ）。
6. 欠測で線を切る処理は #57 の `amedasLinePaths` を使わず、本パネル専用の小さな関数を `areaForecast` 側に持つ（値 null で切る）。動的レンジは `amedasPlotRange` をそのまま再利用してよい。
7. 文字値だけの気温（数値化できない値）は、グラフ上では欠測と同じ「?」とし、原文は読み上げリストにだけ入れる。

### 2.3 前提（統括指示）

- ライブラリは追加しない。SVG 手描き。色は既存トークンのみ。ダークテーマ固定（ライト検証不要）。
- 想定解像度: 主 FHD 1920×1080・1920×960、副 HD 1280×720・iPad 横 1180（×820 想定）。

## 3. 実現方式の比較と推奨

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| (a) 共用部品に任意の行種別（例 `kind: 'chart'`）を追加 | `DetailTimeSeriesTable` がグラフ行を描く | 列幅の同期を部品が保証 | #55・#56・#58 共用部品の改変。特定用途を共用部品に持ち込む。回帰範囲が広い |
| (b) 列ごとのセルに SVG 断片を入れて繋ぐ | 各 `td` に 4rem 幅の SVG、前後の列との中点まで線分 | 日付境界罫線が既存どおり | 列ごとに隣の値が必要。`td` の padding・日付境界の1px罫線で線に継ぎ目・段差。ラベル配置が隣の値に依存し計算が分散 |
| (c) 表全幅の SVG を1セルに span | グラフ行を `cells: [{ span: 列数, content }]` の1セルにし、1枚の SVG に全列を描く | 共用部品は無変更（既存の `span`）。線が途切れず、ラベル配置も1か所で計算できる | 日付境界の罫線が span セルに付かない。列幅が全列同一であることに依存 |

**推奨は (c)**。共用部品を一切変えず（#55・#56 の回帰リスクなし）、線の連続性とラベル配置（隣の線との干渉判定）を1枚の SVG で一括計算できるため。欠点は次で解消する。

- 日付境界: `DetailTimeSeriesTable` と同じ判定（JST 日付が前列と変わる列、先頭列を除く）を本パネル側で求め、SVG 内に `--md-sys-color-outline-variant` の縦線を列の左端 x に描く。
- 列幅: 全列が `'4rem'` であることを描画前に検査する。1列でも異なればグラフを描かず、グラフ行のセルに気温を「9時 15℃」形式の文字の並びで出す（値を失わない代替。通常は発生しない）。

### 4.2 データ

- 列 i の気温 `t[i]`: その列の時点セルが `value` で `value !== null` なら数値、`value === null`（文字値のみ）なら「文字値」、`missing` なら「欠測」、時点の無い列（区間だけの列）なら「対象外」。
- 範囲: 数値の点だけで `amedasPlotRange(values, true)`（最小〜最大に `max(幅×15%, 0.5℃)` の余白、0℃固定下限にしない。同値は ±0.5℃、数値0件は null）。
- 線分: `temperatureLinePaths(values: readonly (number | null)[], x, y): string[]`。数値でない列（欠測・文字値・対象外）で線を切る。補間しない。

### 4.3 座標と寸法

- 列数 N、列幅 64（viewBox 単位＝ルート16px時の CSS px）。SVG は `width: N×4rem`、`height: 8rem`、`viewBox="0 0 {N×64} 128"`、`preserveAspectRatio` 既定（縦横同倍率）。
- 列 i の点の x = `i×64 + 32`（列中心）。
- 描画域（点が置かれる範囲）: y = 30〜98。`y = 98 − (value − low) / (high − low) × 68`。上下各30の余白はラベル（§4.4）の置き場で、点が最高値・最低値でもラベルが SVG 端に触れない。
- 点 `circle r=3.5`、線 `stroke-width: 2`・`fill: none`・`stroke-linejoin: round`、色 `--md-sys-color-primary`。
- 水平補助線（目盛り位置、§4.5）と日付境界の縦線: `--md-sys-color-outline-variant` の 1px。

### 4.4 数値ラベルの配置規則

- 文字: 数値だけ（例「15」「-3」「12.5」。値は `value` をそのまま文字列化し丸めない。単位は付けない）。`font-size: 12px`（viewBox 単位 12）、`font-variant-numeric: tabular-nums`、`text-anchor: middle`、x は点と同じ列中心、色 `--md-sys-color-on-surface`。
- 上下の選択: 点の上（ベースライン y = 点y − 8）を既定とする。ただし隣接する線分がラベル領域に入り込む場合は下（ベースライン y = 点y + 17）に置く。判定は、ラベルの左右端（中心 ±16）における隣接線分の y を求め、上に置いた場合のラベル矩形（上端 点y−18〜下端 点y−5）と交差し、下に置いた場合の矩形（点y+6〜点y+19）と交差しないときだけ下にする。両方交差する場合は上（交差の小さい方）とする。
- 端の保証: 上ラベルの上端は最小でも 30−18 = 12、下ラベルの下端は最大でも 98+19 = 117 で、SVG（0〜128）の内側に収まる。
- 横の重なり: ラベル幅は最長「-10.5」5文字×約7 ≒ 35（半幅約17.5）で、列中心の間隔64より十分狭く、隣の列のラベルとは重ならない。先頭・末尾列でも中心から端まで32あり、セル端を越えない。
- 縦の目盛りとの重なり: 目盛り数値は SVG の外（sticky の行見出し列内）に置くため重ならない。
- 補助線・日付境界線との重なり: ラベルに `paint-order: stroke`、`stroke: var(--md-sys-color-surface-container-high)`、`stroke-width: 3` の縁取りを付け、線の上でも読めるようにする。
- 実挙動の確認: 上記の数値は設計時の見積りで、ブラウザでの文字幅は**実挙動未確認**。AC-4 で矩形の非交差を実測する。

### 4.5 行見出しと目盛り

- 行見出し `header` は ReactNode で「気温（℃）」と縦軸の目盛り数値を入れる。行見出し列は既存どおり sticky で、横スクロールしても目盛りが見える。
- 目盛り: `range` の中の整数のうち、刻み {1, 2, 5, 10}℃ から目盛りが2〜4本になる最小の刻みの倍数。数値だけを `--md-sys-color-on-surface-variant` で表示し、縦位置は SVG の y と同じ比率で行見出しセル内に絶対配置する（見出しセルの上下 padding は 0、高さ 8rem）。目盛りは `aria-hidden`。
- 数値の点が0件（range null）: 目盛り・補助線・線・点を描かない。

### 4.6 欠測・文字値・対象外の見せ方

| 列の状態 | 点・線 | ラベル |
| --- | --- | --- |
| 数値 | 点あり、前後の数値の点と線で結ぶ | 数値 |
| 欠測（`missing`） | 点なし、線を切る | 描画域中央（y = 64 付近）に「?」を `--md-sys-color-on-surface-variant` で表示（#55・#56 の欠測表記に合わせる） |
| 文字値のみ（`valueNumber` null・`valueText` あり） | 点なし、線を切る | 欠測と同じ「?」。原文は読み上げリスト（§4.7）にだけ入れる（オーナー決定 2026-09-29） |
| 対象外（時点の無い列） | 点なし、線を切る | 表示なし |
| 数値の点が0件 | 何も描かない | 欠測・文字値の列の表示は上表どおり。すべて欠測なら SVG 中央に「気温の予想なし」を1つだけ表示し、列ごとの「?」は出さない |

### 4.7 読み上げ

- SVG・目盛りは `aria-hidden="true"`。
- グラフ行のセル内に、視覚的に隠したリスト（`<ul>`、CSS は既存 `.detail-ts-caption` と同じ隠し方の本パネル用クラス `.af-visually-hidden`）を置き、各列を1項目にする: 「2026年9月28日（月）9時、気温15度」「…12時、気温欠測」「…15時、気温 {原文}」（文字値のみの列。画面には原文を出さない）。対象外の列は項目を作らない。数値0件でも欠測項目は並べる。
- セルの `ariaLabel` は付けず（リストの読み上げを妨げないため）、行見出しの読み上げは「気温（℃）」。
- 方式の選定理由: セルの `aria-label` に全時点を連結すると1つの長い文になり、時点ごとに移動して聞けない。リストなら支援技術で1項目ずつ辿れる。

### 4.8 CSS

- グラフの `td` は `.af-detail .detail-ts-table td:has(> .af-temp-chart)` で `padding: 0`、行見出し `th` は `:has(> .af-temp-chart-header)` で上下 padding 0（共用部品にクラス入力を足さないため `:has` を使う。Safari 15.4 以降・Chromium 105 以降で有効）。
- `svg` は `display: block`。
- HEX を CSS・TSX に書かない。

### 4.10 高さ見積り

詳細の表: 見出し2段 約56px ＋ 天気 約64px ＋ 風 約48px ＋ 気温グラフ 128px ≒ 296px（数値行 約28px の削除でグラフ追加前との差は +100px）。ダイアログの見出し・余白を含めても HD 720（ダイアログ上限 648px）に収まる見込み。**実挙動未確認**、AC-7 で実測する。

## 5. 状態ごとの寸法の揺れ

すべての状態でグラフ行の高さ 128px、SVG 幅 N×64px、行見出し列の幅を変えない。

| 状態 | 表示 |
| --- | --- |
| 通常（複数点、変化あり） | 線・点・ラベル・目盛り |
| 途中欠測 | 欠測列で線が切れ、「?」 |
| 1点のみ | 点1つ（線なし）とラベル、範囲は値±0.5℃ |
| 全点同値 | 水平線、全ラベル上側、範囲は値±0.5℃ |
| 急な上下（隣の線がラベル領域に入る） | 規則により一部ラベルが下側 |
| 負値・2桁・小数（「-10.5」等） | ラベル幅が増えても隣と重ならない |
| 文字値のみの列 | 点なし、「?」（§4.6） |
| 全欠測 | 「気温の予想なし」だけ |
| stale | 前回値のグラフを装飾なしで表示 |
| 列幅が 4rem 以外を含む | グラフを描かず文字の並び（§3） |

## 6. 開発フィクスチャ

`?panelFixture=area-forecast` の合成データの気温を、途中に欠測1点・文字値1点（グラフ上は「?」、原文は読み上げリストだけで確認）・負値・2桁・小数（例 `-10.5`）・隣と大きく差のある点を含む値にし、区間の無い最終列にも値を置く。状態確認用に、開発ビルド限定のクエリ `afTempCase=single|flat|empty|text` を追加し、指定時だけ気温を「1点のみ」「全点同値」「全欠測」「全点文字値のみ」に差し替える（既存フィクスチャ名と API 抑止判定は変えない。本番ビルドでは無視）。「確認用データ」表示は既存どおり。

- 列幅を 4rem 以外に変える場合、グラフは文字の並びの代替表示になる（§3）。列幅の変更時は本グラフの座標計算も改めること。
- 朝の最低・日中の最高気温の線は将来課題（確定事項4）。
