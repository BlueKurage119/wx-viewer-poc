# Codexの作業環境とワークツリーの確認

対象: 統括担当と各フェーズの担当。作業範囲・承認の制約は[AGENTS.md](../../../AGENTS.md)、既存差分の扱いは[設計業務標準](../02-design-protocol.md)・[検収業務標準](../04-inspect-protocol.md)を参照。本書は確認方法の例であり、権限や必須工程を追加しない。

## 作業場所を見分ける

Codexで別タスクや別ワークツリーを扱う際、表示中のタスクとコマンドの作業ディレクトリが同じとは限らない。次の読み取り操作を組み合わせると、対象を取り違えにくい。

```bash
pwd
git worktree list --porcelain
git branch --show-current
git rev-parse HEAD
git status --short
git diff --stat
git diff --cached --stat
```

`worktree list`で登録場所とブランチを対応づけ、対象ディレクトリをコマンドの作業場所に指定してから、その場所のHEAD・差分を確認するとよい。ブランチ名が空ならdetached HEADの可能性があるため、想定ブランチにいる証拠にはしない。

差分の有無だけでは、誰の変更かは分からない。開始時の状態と今回の差分を照合すると、他者の作業を自分の成果としてコミットしたり、終了時に消したりする誤りを防ぎやすい。他者が作業中の場合、読み取った状態はその時点のものであり、その後も同じとは限らない。

## 読める場所と書ける場所は別

本プロジェクトの規程改訂では、別ワークツリーを読み取りできても、編集には実行環境の許可が必要だった。これは観測したセッションの設定であり、すべてのCodex環境に固定の制約ではない。

権限エラーが出た場合は、対象パスと現在の書き込み許可範囲を照合すると原因を切り分けやすい。対応はそのセッションの承認機構に従う。環境の実行許可は、設計・対象範囲・マージの承認を代替するものではない。

## ワークツリーで分離されないもの

Gitワークツリーは作業ファイルを分けるが、リポジトリのGitメタデータは共有する。ホスト上のポートやプロセスも、ワークツリーを分けただけでは隔離されない。検証サーバーの衝突は、作業ディレクトリの違いだけでは判断できない。関連する禁止事項は[開発フロー業務標準](../01-dev-workflow-protocol.md)を参照。
