# devサーバー作法の背景

対象: 製造担当・検収担当。禁止事項の本体は[01-dev-workflow-protocol.md](../01-dev-workflow-protocol.md)の「devサーバーの禁止事項」を参照。

**出典:** `mj-stats-viewer`での差し戻し事例。オーナーが検証用に自分でdevサーバーを立てていた回に、エージェントが無関係なサーバーごと一括終了させた。ポート番号は日によって違うことがあるため固定で覚えず、その都度の状況を確認する(例: 停止は`pkill -f "vite --port <自分のポート>"`のようにポート指定で行う)。wx-viewer-pocは`npm run dev`でweb(5174)+api(3001)を固定ポートで起動する(README参照)。

## APIが応答しない・データが出ないときの確認

**出典:** Issue #45・#46の検収。何度も「応答なし」と誤判断し、待ち時間を失った。

- **夜間帯は新しいデータが入らず、ナウキャストのコマが0件になりうる**: `config/polling.yaml`の20:00〜04:00は、定期取得と、未キャッシュの画像の上流取得が止まる(`catalogAccess.allowed=false`、`reason=scheduled_stopped`。基本設計の「検証済みキャッシュ読取可」は維持される)。保存済みの索引は読めるが、ナウキャストは表示窓(現在の前後60分)で絞って返すため、最後の取得から60分以上たつと0件になる。キキクルは保存済みの全フレームを返す。夜間に新しいデータで実機確認するには、同ファイルの該当期間をローカルで日中並みに変え、APIを再起動する。保存済みのデータで足りる確認(キキクルの索引、取得済みのタイルなど)では、変更は要らない。このファイルは追跡対象で、ローダーに既定値フォールバックがないため、追跡から外してはいけない。ローカル変更が混ざるので、`git add`は必ずパスを指定し(`-A`・`.`を使わない)、コミットしない。
- **`npm run build`はAPIを再起動させる**: `packages/shared/dist`が更新され、`tsx watch`がAPIを再起動する。再起動後は初期化が終わるまで応答しない(起動時再処理が重い間は、最大約15分。Issue #168)。`build`や`apps/api`・`packages/shared`の編集は、APIの応答を待つ前に済ませ、応答した後は避ける。
- **応答待ちはポーリングで行う**: 数十秒で「応答なし」と判断しない。`until curl -s --max-time 10 -o /dev/null -w "%{http_code}" <URL> | grep -q "^200$"; do sleep 10; done`をバックグラウンドで走らせる。
- **降水がない日の見え方の確認**: 凡例色とタイルの着色の一致などは、降水域がないと確認できない。無降水なら、降水のある地域(例: 新潟県付近、ズーム10のタイルで`907/395`あたり)へ地図を動かして確認する。保持レイヤーは`moveend`で破棄されるので、再生間隔などの計測は、移動を終えてから始める。
