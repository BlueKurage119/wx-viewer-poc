# 指示体系(docs/rules)について

## 位置づけ

```
CLAUDE.md・AGENTS.md（権限と責任: 絶対禁止事項、役割と担当の対応表）
        │
        ▼
業務標準(docs/rules/、このディレクトリ直下) — 必ず通る手順と合否条件
        │
        ▼
指導文書(docs/rules/advisory/) — 手順を実行するための知識・ノウハウ・過去事例
        │
        ▼
スキル・エージェント定義（.claude/agents/*.md 等）— 標準の実行支援・入口
```

- **CLAUDE.md/AGENTS.md**: 誰が何をしてよいか(権限)、何をしてはならないか(禁止事項)。短く、常に読む。
- **業務標準(このディレクトリ直下)**: 各フェーズが必ず通る手順・必須の実施項目・合否条件。ここに書かれた必須事項は省略できない。数が少ないため`docs/rules/`直下に平置きし、サブディレクトリを設けない。
- **指導文書(`docs/rules/advisory/`)**: 業務標準に定めた手順を上手にこなすための知識(具体的な検証コマンド、環境固有の罠、過去の失敗事例、判断が難しいケースの解説)。今後の蓄積で数が増える見込みのため、専用サブディレクトリに置く。
- **スキル・エージェント定義**: 業務標準の実行を支援する入口(実行コマンド、フォーム、対話手順)。

## 統治原則

> **スキル・指導文書は、業務標準が定める権限、必須工程、合否条件を追加・変更しない。必須化が必要な教訓は、業務標準の改訂として扱う。**

指導文書に「こうした方がよい」と書いた注意点が、いつの間にか事実上の必須工程になってはならない。逆に、本来必須のはずの確認が指導文書の奥に埋もれて省略されてもならない。「これを外したら合否・権限の範囲が変わるか」で判定する。

- 変わる → 業務標準に書く(短い必須事項として)
- 変わらない(やり方が下手になるだけ) → 指導文書に書く

## 業務標準の一覧

- [01-dev-workflow-protocol.md](01-dev-workflow-protocol.md) — Issue駆動の4フェーズ運用順序、設計→製造の承認ゲート、AGY/Antigravity委託の必須記載事項、ブランチ・コミット・PR・署名の必須要件、devサーバーの禁止事項
- [02-design-protocol.md](02-design-protocol.md) — 設計担当の権限境界(自分で決めてよい範囲)、設計書に必ず含める項目
- [03-build-protocol.md](03-build-protocol.md) — 製造担当の権限境界(設計書からの逸脱時の対応)、スコープ制約
- [04-inspect-protocol.md](04-inspect-protocol.md) — 検収担当が着手確認から終了確認まで必ず通る7段階の手順と合否条件
- [05-verification-protocol.md](05-verification-protocol.md) — テスト追加時・検証時に必須の手順順序(red確認→対照実験)とアサーションの原則(発見の分類義務は[04-inspect-protocol.md](04-inspect-protocol.md)を参照)
- [06-ui-md3-protocol.md](06-ui-md3-protocol.md) — apps/webで必ず守る技術制約(sideEffects・パッケージ固定・生タグ禁止・localStorageキー同期)

各ファイルの「必須事項」は上から順に実行できる構成にしてある。手法の詳細・具体例は該当する[docs/rules/advisory/](advisory/README.md)のファイルにリンクする。

## 番号体系

- **業務標準**(このディレクトリ直下): `[番号]-[タイトル].md`。番号はフェーズ・トピック順の固定番号で、`docs/rules/advisory/`の対応ファイルと同じ番号を可能な限り揃える。
- **指導文書**(`docs/rules/advisory/`): `[プレフィックス]-[番号]-[タイトル].md`。
  - プレフィックスは対象AI製品を表す: `A`(Codex・Antigravity対象)、`C`(Claude対象)、`G`(製品非依存の共通知識)。`products` frontmatterが示す「今どの製品がこのフェーズを担当するか」とは別軸で、「内容そのものが特定製品のツール・挙動に依存するか」で判定する。
  - 番号はプレフィックスごとに独立した発行順の連番とする(A/C/Gそれぞれ1から数える)。
  - 既存番号は不変。途中への追加は枝番、末尾への追加は続番、削除は欠番とする(`docs/design/issue-N-*.md`の運用を踏襲)。

`docs/rules/advisory/README.md`にfrontmatterスキーマの詳細を記載する。
