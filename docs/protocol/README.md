# 業務標準(Protocol)について

## 位置づけ

```
CLAUDE.md・AGENTS.md（権限と責任: 絶対禁止事項、役割と担当の対応表）
        │
        ▼
業務標準(docs/protocol/、このディレクトリ) — 必ず通る手順と合否条件
        │
        ▼
指導文書(docs/advisory/) — 手順を実行するための知識・ノウハウ・過去事例
        │
        ▼
スキル・エージェント定義（.claude/agents/*.md 等）— 標準の実行支援・入口
```

- **CLAUDE.md/AGENTS.md**: 誰が何をしてよいか(権限)、何をしてはならないか(禁止事項)。短く、常に読む。
- **業務標準(このディレクトリ)**: 各フェーズが必ず通る手順・必須の実施項目・合否条件。ここに書かれた必須事項は省略できない。
- **指導文書(`docs/advisory/`)**: 業務標準に定めた手順を上手にこなすための知識(具体的な検証コマンド、環境固有の罠、過去の失敗事例、判断が難しいケースの解説)。
- **スキル・エージェント定義**: 業務標準の実行を支援する入口(実行コマンド、フォーム、対話手順)。

## 統治原則

> **スキル・指導文書は、業務標準が定める権限、必須工程、合否条件を追加・変更しない。必須化が必要な教訓は、業務標準の改訂として扱う。**

指導文書に「こうした方がよい」と書いた注意点が、いつの間にか事実上の必須工程になってはならない。逆に、本来必須のはずの確認が指導文書の奥に埋もれて省略されてもならない。「これを外したら合否・権限の範囲が変わるか」で判定する。

- 変わる → 業務標準に書く(短い必須事項として)
- 変わらない(やり方が下手になるだけ) → 指導文書に書く

## frontmatter

`docs/advisory/`と同じスキーマ(`title`/`description`/`phases`/`products`)を使う。業務標準であることは配置ディレクトリで示し、frontmatterに追加のフィールドは設けない。
