# Issue化ドラフト（実装タスク単位）

作成日: 2026-09-08

本ドキュメントは [基本設計](basic-design.md) を実装タスク単位に分解したIssue案の下書きである。GitHubへの起票前のレビュー用。各タスクは対応する基本設計の章番号を明記する。優先度ラベルは付与しない（本セッションでの決定）が、§1で確定した「§4（ナウキャスト・キキクル切替）はC109が冬季開催のため実装順序で優先度を下げる」という方針は踏まえ、着手順の参考として文中に注記する。

粒度は「実装タスク単位」とし、1タスク=1〜3日程度を目安とする。実装が進むにつれて分割・統合してよい。

## Epic A: プロジェクト基盤・共通

- **A1. プロジェクト初期化（React + TypeScript + Vite + Node.js）**
  §2。`wx-viewer-poc`のフロント／バックエンド雛形を作成し、Material Webを導入する。lint/format設定を整備する。
- **A2. 共通シェルレイアウトの実装（ヘッダー・左ナビレール・下部通知領域）**
  §3。3.1〜3.3全ビューで共有する固定シェル（ヘッダー、ナビレール、最下部通知領域）を実装する。`terminalMode: 'H' | 'K'` パラメーターを用意し、Hモードでナビレールから3.3を非表示にできるようにする（§3）。
- **A3. 共通メタ情報の型定義（source, issuedAt, validAt/From/To, fetchedAt, lastSuccessAt, availability, sourceVersion）**
  §6.2。全情報種別APIが共通で持つメタ情報の型を定義する。
- **A4. availability状態遷移の実装（available/stale/unavailable）**
  §6.3。共通ロジックとして状態遷移判定を実装し、単体テストを書く。
- **A5. 警戒レベル・通知区分のセマンティックカラートークン定義**
  §5.7、Issue #1設計§3.4.2・§3.4.4。気象庁警戒レベル配色（黒/紫/赤/黄）と通知区分色（警報/問いかけ/非常ブザー、受信異常等）を`--wx-alert-*`等の固定セマンティックトークンとして一括定義する。Issue #2試作でコンポーネントCSSへ暫定的に直書きした値（警報行・問いかけ行の背景色、受信異常バナー）を置き換える。
